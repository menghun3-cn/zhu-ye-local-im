# Agent Note: 变更日志门禁需要补齐历史条目

Status: implemented

[English](2026-11-06-changelog-gate-backfill.md) | 中文

## Problem

`dart test` 在 `test/process/changelog_entries_test.dart` 上有七处失败。
三个发布 tag——`v0.1.30`、`v0.1.31`、`v0.1.32`——在 `CHANGELOG.md` 里完全
没有条目，它们的 GitHub Release 说明和应用内更新说明因此是空的。另有六个
已发布版本包含未被任何条目提及的用户可见提交：英文提交主题只产生英文
片段，而条目正文是中文，测试里的 `translated` 词表没有覆盖涉及的高频
功能词（`download`、`presence`、`secret`、`image`、`low-frequency`）。
`v0.1.27` 的两个 `docs:` 提交则是条目里确实缺失。

## Decision

补齐而不是放宽：

- 按各 tag 实际包含的提交补写 `0.1.30`、`0.1.31`、`0.1.32` 条目，日期为
  2026-11-03。`0.1.32` 只带了发布 chore，因此条目里明确写明这一点。
- 为 `0.1.27` 补上两条缺失内容：AGENTS.md 安全红线文档变更（原有条目
  补上文件名，使 `agents` 片段能命中）与官网下载区移除 Android 试用标签。
- 在 `changelog_entries_test.dart` 的 `translated` 词表中补入缺失的高频
  功能词。词表本就是为这类缺口设计的扩展点；新增片段只会把误报变成通过，
  不可能反向。

## Alternatives considered

**整体重写失败的条目。** 否决：条目就是那些版本发布时公布的内容，测试
自己的原则是事后改写的发布说明不再是当时宣布的内容。修复只动真正缺失的
部分。

**把版本或提交排除在检查之外。** 否决：豁免清单正是门禁腐化的方式。这些
tag 真实存在并已发布，条目也必须存在。

**要求中文条目里出现英文片段。** 否决：这会让今后每个英文主题的提交都
失败，直到有人为了迁就匹配器去改写正文。翻译词表的存在正是为了让中文
条目可以指称英文命名的功能。

## Consequences

`dart test` 在 develop 系历史上恢复全绿。当新的高频功能名开始产生
「提交未被提及」的误报时，先在翻译词表里扩展，而不是改写已发布的条目
去迁就匹配器。
