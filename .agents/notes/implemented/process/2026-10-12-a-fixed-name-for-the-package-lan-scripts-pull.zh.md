# Agent Note: A fixed name for the package LAN scripts pull

Status: implemented

[English](2026-10-12-a-fixed-name-for-the-package-lan-scripts-pull.md) | 中文

## Problem

本仓库产出的每个产物，文件名里都带着版本号：
`LocalTransfer-<版本>-windows-x64-portable.zip`、`…-setup.exe`、`…-android.apk`。
这是有意的 —— 名字不说自己是什么的包，会被装两遍、被讨论错 —— 代价是名字每次发版都变，
而按 `AGENTS.md` §9 的节奏，几乎每次发版都要动。

于是局域网里那些从一台机器（服务 `build/dist`）拉包的脚本，没法把这个名字写死。今天它
只有两条路：每次发版都去改一次；或者抓一份目录列表再按模式匹配 —— 后者取决于对面是哪个
HTTP 服务器、它怎么渲染目录索引。两条路都不是这个包的属性，都是会**悄悄过时**的杂活。

GitHub 解决不了这个场景。`releases/latest` 是「最新的那个 release」，不是一个文件：
`releases/latest/download/<名字>` 照样得先知道带了版本号的准确附件名，所以唯一与版本无关的
URL 还得先问一次 API。而局域网场景恰恰是**网络可能根本到不了 GitHub** 的那种 —— 提供
`build/dist` 的那台机器自己就是分发通道。

在此之前，仓库里没有任何东西发布过一个与版本无关的名字。

## Decision

`scripts/publish-latest.ps1` 针对一个源文件发布一个名字里没有版本号的别名：把源文件按固定名
复制到同一个目录里，再写一个 `<别名>.sha256` 侧车，内容是复制过去那份的哈希。

两个打包脚本都在自己的校验通过之后**最后一步**调用它 —— `pack-windows-portable.ps1` 在 zip
被读回来核对过（以及可选的冒烟跑过）之后，`pack-windows-installer.ps1` 在安装包核对过之后。
两个名字是：

- `LocalTransfer-latest-windows-x64-portable.zip`
- `LocalTransfer-latest-windows-x64-setup.exe`

这个次序给出的是别名值得被信任的那个不变式：**`latest` 存在，当且仅当有一个包通过了全部
检查。** 中途任何一步失败的运行都不会碰上一版的别名 —— 旧，但是已知是好的 —— 而不是把一个
没通过检查的包发布出去、指望失败之后有人注意到。

有两个细节是承重的，不是装饰。

**别名是改名发布，不是覆盖写。** 脚本先把源文件复制成 `<别名>.new`，再把它改名到别名上，
因为同卷内改名是原子的：与重打并发运行的拉取方读到的要么是上一版、要么是新的一版，不会是
写了一半的那一份。就地覆盖写会留下一段「文件已经截断、内容还没重新填满」的窗口，而正好落在
那个窗口里的拉取方，拿到的是一个长度看着合理、解压却报错的文件 —— 那比文件不存在难查得多。

**复制完之后脚本会重新算一遍别名的哈希**，对不上就拒绝发布。别名的全部意义就是「这就是那个
刚验完的包」；一次悄悄没发生的复制，比没有别名更糟。

侧车按 `sha256sum` 的格式写（`<小写十六进制><两个空格><文件名>`），不带 BOM、只用 LF。拉取方
因此能验一次「这个走 Wi-Fi 下完的大文件是不是完整的」—— 最可能被它抓住的就是这个失败 —— 而且
用的是它们自己的工具本来就认的格式，不是本仓库自创的一种。写进去的哈希是对**带版本号那份**
算出来的，所以别名和它复制的那一份可以拿同一个值去对。

发布规则只有一处实现。每个打包脚本只提供自己的产物和要给它起的名字；没有谁去重新实现复制、
改名或哈希校验。`pack-windows-installer.ps1` 的头注释早就在校验这件事上这么论证过 —— 被写两遍
的规则，就是两个文件可能互相打架的规则 —— 而别名规则是同一类规则。

**`release.yml` 的产物路径在同一次提交里改了。** 原本是 `build/dist/*-portable.zip` 和
`build/dist/*-setup.exe`，两个通配都命中别名；放着不管的话，一次发布就会带上五个附件，而不是
三个，其中两对和旁边的兄弟文件逐字节相同。现在路径显式写出名字里的版本号。Releases 页面上的
数量仍然是三个，这与[产物那篇笔记](2026-10-12-a-tag-builds-the-three-packages.md)和 `AGENTS.md`
§9 的说法一致。

## Verification

在把任何一个打包脚本接上去之前，别名脚本先被单独跑过：首次发布、在已有别名上重发一次、以及
三处拒绝（源文件不存在、`-Name` 里带了目录、源文件是空的）。侧车被按字节读回来确认没有 BOM、
没有 CR，内容也与 `Get-FileHash` 对过。成功运行后不留下 `.new` 文件这一条也查了。最后两个打包
脚本各跑一次，产出的别名被打开并与各自的源文件比过哈希。

## Alternatives considered

**用 `Copy-Item -Force` 直接写到那个名字上。** 这个功能最短的写法 —— 每个打包脚本一行。它输在
上面说的那个截断窗口上，也输在没法发现一次没发生的复制上。改名写法付出的成本是一个只活几毫秒
的临时文件。

**让 CI 的通配把别名也捞上、附到 Release 上。** 免费的 —— 路径本来就命中 —— 而且能给能上外网的
机器一个稳定 URL：`releases/latest/download/LocalTransfer-latest-windows-x64-portable.zip`。它输在
让一次发布对两个文件各带两个名字，而这正好在用户做决定的那个当口招来「我该下哪个？」；也输在
发布侧的「最新」本来就已经存在，而且不是一个文件名 —— 它是那个 tag。把它们排除在外，成本是
工作流里一条注释。

**把同样的逻辑在两个打包脚本里各写一遍。** 输给「共享规则只该有一处实现」。原子改名和复制后
复算哈希恰恰是那种会只在一个文件里被修好、在另一个文件里继续错着的东西，而两个脚本各自的评审
都看不出来。`scripts/` 里多一个脚本是更便宜的错。

**一个叫 `latest.zip` 的目录联接或符号链接。** 输在：在 Windows 上建它需要提权或开发者模式；
它活不过一次「拷到共享盘 / 打进 zip / 跨到不支持链接的文件系统」；静态文件服务器可能拒绝跟随它。
一个真文件很无聊，而且总是管用。

**一份 `latest.txt` 清单，同时列出两个产物和两个哈希。** 诱人之处是拉取方顺便能拿到版本号；输在
它有两个写者：绿色包脚本只知道 zip 的哈希，安装包脚本只知道 exe 的，于是每次运行都得读回对方的
那一半再写回去 —— 凭空造出来的合并问题。每个产物一个 `<别名>.sha256`，让每个产物恰好只有一个
写者，而 `sha256sum -c` 本来就认这个格式。

**让绿色包脚本把两个别名都发掉。** 它先跑，所以安装包那时还不存在；发它的别名要么意味着写一个
指向上一版安装包的名字，要么为了一个与两者都无关的规则去调整两个脚本的先后。每个产物的别名由
产出它的那个脚本发布。

## Consequences

**换来了什么。** 局域网侧的拉取方有了固定 URL，也有了验证拿到的东西的手段。别名不可能是没通过
检查的包，因为它是检查之后才写的。重打的时候有别的东西正在下载也安全。用它不需要先懂什么版本号。

**付出了什么。** `build/dist` 现在放着一对带版本号的、一对别名、两个侧车；而每个别名的新鲜程度
只等于写它的那个脚本最后一次成功运行。单独跑 `pack-windows-installer.ps1` 会更新安装包别名，而把
zip 别名留在它上次见到的那个构建上 —— 所以两个别名可能来自不同的构建。这一点是被接受而不是被
修掉的：每个别名说的是自己的产物，两个脚本都会打印它们发布的版本；而另一条路（把两个脚本耦合成
谁也离不开谁）会拿掉「一个脚本能被单独运行」这个能力，而那正是安装包通常的重建方式。

**没有覆盖的。** 别名不表达「比你手上的更新」。它是一个名字，不是一次比较：想知道要不要更新的
拉取方，应该从它已经持有的包里读出版本 —— 绿色包的 `使用说明.txt` 第 1 行是版本、第 4 行是
commit —— 或者拿存下来的哈希跟侧车对。

**门禁套件仍然没有行使它。** `AGENTS.md` §5 里没有任何一道门禁会跑这两个打包脚本；别名第一次被
行使，是在某次打包或某个 tag 运行的时候。一个在 pull request 上跑这两个打包脚本的 CI 作业会覆盖
这件事和它的两个前任（[少了 D 的那个定义](../bug-fix/2026-10-12-a-define-that-was-spelled-without-its-d.md)、
[只在一边跑过的两步构建](../bug-fix/2026-10-12-two-build-steps-that-had-only-ever-run-on-one-side.md)），
而那个作业还没有写。
