# Agent Note：首屏终于把那件东西摆出来了

Status: implemented

## Problem

关于官网的三条要求，弱点其实是同一个：页面通篇在用文字描述这个程序，却从来没把它
摆出来给人看。

1. 下载区最后一条 callout 在教读者「要写脚本自动拉包，就用这两个固定地址」，
   附两条 `releases/latest/download/...` 与各自的 `.sha256`。要求是删掉。
2. 「服务器 / 账号 / 云端 / 外网请求」四联，原先是四格网格，每格上面是标签、
   下面是「没有」或「仅『检查更新』」。要求是换一种展示样式，内容不变。
3. 页面最上面只有文字。要求是右边加一张图、倾斜展示，左边「两台设备之间传东西……」
   那段文案原样不动。

第 3 条的麻烦在于：这个页面全部的卖点就是「你自己的两台设备，在你自己家的网络上
说话」，而页面上没有一张两台设备在说话的图。现成的截图都在
`design-preview/_shots/` 里，而那个目录**没有入 git** —— 官网就算想引用也引用不了。

## Decision

**首屏改成双栏，官网也因此多出第一个二进制资产。**

- `site/assets/hero.png`（1284×769，73 KB）是从
  `design-preview/_shots/conversation.png` 里裁出来的会话页窗口。裁剪是精确的：
  原图 1360×980，底部约 150 px 是设计稿的调试注释（「局部微调说明……」「配对回到
  列表行上……」），那些不能上线。窗口自己的发丝边框在 x 38–1321、底边在 y 824，
  裁剪框是 `(38, 56, 1322, 825)` —— 是**按边框颜色匹配**找到的，不是目测：页面底色
  是 `#E9EBEF` 不是白色，用「非白即内容」取包围盒会把底部注释一起吞进来。
- **复制，不是引用。** `design-preview/` 未入 git，部署出来的页面会拿到一个 404。所以图现在是 `site/` 下受版本管理的文件。这同时改写了
  `2026-10-12-the-site-is-files-not-a-build.md` 的结论——那里说「官网是三个文件，
  仅此而已」：现在是三个文件外加一张图，而这也正是「没有构建步骤」这句话唯一不再
  字面成立的地方。裁剪是手工做了一次，从此以后它作为 diff 被审阅。
- **倾斜用 2D，不用 3D。** `transform: rotate(-2.4deg)`（860 px 以下 1.2°）。
  `perspective()` 那种倾斜会更「有设计感」，但也会把界面里每一个字都柔化一遍 ——
  而这张图存在的全部理由，就是证明界面是清清楚楚的。
- **文字栏比图栏宽一成**（`1.1fr / 1fr`）。标题是手工断行的两行字；在等宽栏里
  第一行会在展示字号下溢出，而那样的修法只能是缩小字号，是错的交换。标题字号用
  `clamp(34px, 3.6vw, 48px)`，保证它在 960 px 到 1080 px 容器之间不会跑出自己的栏。
- **四联改成胶囊，不是另一种网格。** 每枚胶囊带一个标记：前三枚是圆里一道斜线
  （确实没有），最后一枚是实心点 —— 因为那一项不是「没有」，是「只有这么一点」，
  打叉等于说了反话。960 px 以下整条堆成一列。

## Testing

- 用无头 Chrome 实际渲染了四张：1280×900 浅色、1280×900 深色（改一份一次性副本来
  绕开首屏内联脚本按系统偏好重设主题）、390×1400 窄屏、1280×2200 整页。四张都对：
  任何宽度下标题都不溢出、图永远不会撞上文案（32 px 栏间距吃下了旋转量）、胶囊是
  换行不是横向滚动、下载区在 SmartScreen 那条之后就结束了。
- 删掉的那段确实没了，也没有别处引用它：`site/` 下 `grep` 不到 `latest/download`，
  也找不到 `sha256sum`。`.callout code` 规则保留，注释随之改写 —— 当初要它的理由
  （一条比容器还长的地址）已经没了，但长路径与长哈希本来就没有自然断点。
- 没有改任何 Dart、工作流或打包输入，六道门禁按构造不变；仍然照跑一遍。

## Alternatives considered

**用 3D perspective 倾斜。** 否：它会柔化截图里的文字，而这张图要的就是界面清楚。

**直接引用 `design-preview/_shots/conversation.png`。** 否：那个目录未入 git，
  部署出来的官网会在自己的首屏上 404。把文件复制进 `site/assets/` 是唯一能在全新
  clone 里也活下来的版本。

**画一张插画而不是用截图。** 否：「两台设备传文件」的插画等于把产品画了一遍，
  而这一页的职责就是把产品亮出来。官网与 `design-preview/` 本来就共用一套令牌，
  截图是不花钱的那个对齐选项。

**把固定地址那段往下挪、留着。** 否：要求就是删掉，而且那是维护者才关心的信息 ——
  它在 `release.yml`、`CHANGELOG.md` 和 Release 说明里，写脚本的人本来就会去那些
  地方找。

**四联留着网格、只改皮肤（加分隔线、键改大写）。** 否：那是同一种读法换了层漆。
  胶囊改的是这条要说的话 —— 一件事一件事被划掉，而这正是这些内容一直以来的意思。

## Consequences

**换来的。** 第一屏就能看见产品，文案一个字没动，四个「没有」读起来像一连串否定，
  而不是一张参数表。

**让掉的。** `site/` 不再是整整三个文件。今后任何「直接把目录拷过去」的思路都得把
  `assets/` 算进去，而里面唯一那张图是手工裁的，没有脚本能复现 —— 界面改了，就得
  有人再手工裁一次。

**欠着的。** 这个分支什么都不会上线：`master` 只收 `release/*` 的 PR，所以新首屏
  要等下一次发布（或者手动跑一次 `pages.yml` 的 `workflow_dispatch`，它就是为这个
  准备的）。
