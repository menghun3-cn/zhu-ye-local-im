# Agent Note: 删除文件必须用绝对路径

Status: implemented

[English](2026-10-28-deleting-files-needs-an-absolute-path.md) | 中文

## Problem

2026-10-28，主检出区被从内部删除。起因是要清理一个名为 `$null` 的杂散文件：PowerShell
调用 `cmd /c rd` 时，`$null` 先被展开成空值，真正到达 `cmd.exe` 的 `rd /s /q` 指向了
仓库根目录而不是这个文件。工作树连同 `.git` 一起消失，检出区只能从远程重建。

问题不在「想清理」，也不在那个文件本身；问题是破坏性命令跨了 shell 边界，而且从来没有
校验它要作用在哪个路径上，一次被拒绝或失败的删除还继续重试，而不是停下来报告。

## Decision

`AGENTS.md` §7.1 的安全红线对本仓库内的一切 Shell 命令（包括 AI 助手）有约束力：

- **禁止跨 shell 的破坏性命令。** PowerShell 进程不得对「先前步骤算出来或枚举出来的路径」
  执行 `cmd /c rd`（或任何 `cmd` / bash 的文件变更）。删除与移动必须在同一种 shell 里用
  它自己的原生语法完成。
- **清理不是目标。** 杂散文件（比如意外生成的 `$null`）属于「忽略」，不属于「主动清除」，
  除非用户明确要求清理。宁可留一个没删掉的文件，也不要为了动它而让破坏性命令碰到仓库。
- **删除/移动前先解析并校验。** 动作前目标的绝对路径必须解析出来，并且等于预期的字面量
  路径；它不能等于仓库根目录，也不能是仓库内任何要保留的内容。命令末尾不得是未展开的
  变量或通配符。
- **`$null` 不是文件名。** PowerShell 里 `$null` 是空值。把它放进 `cmd /c "..."` 字符串会
  展开成空，让删除落到仓库根目录。丢弃输出用 `2>$null`（PowerShell）或 `2>/dev/null`
  （bash），两种 shell 不要混用。
- **一次失败的删除/移动就是停止信号。** 出现 `Access is denied`、文件被占用这类错误后，
  不得重试，也不得换工具再试，必须先向人报告「什么还完好、下一步可能是什么」。
- **仓库内容用移动，不用删除。** 挪动检出区先整体移到中间的安全路径，确认新位置完好后，
  才处理旧位置；不删除仓库内任何文件。

## Alternatives considered

**专门做一个「删除」技能并带确认提示。** 暂缓：上面这套规则已经把危险命令的形状挡掉了，
多加一个组件只会多一个「跳过它」的地方。

**用户要求清理时就允许跨 shell 删除。** 否决：2026-10-28 正是从「没人要求的一次清理」
开始的。越是想清理，破坏性命令越要少耍聪明，而不是更多。

## Consequences

- 每个 agent 和贡献者现在都有一节有约束力的安全规则（`AGENTS.md` §7.1），它优先于一切
  便利。
- 检出区被删后的恢复方法已记录：远程
  （`https://github.com/menghun3-cn/zhu-ye-local-im.git`）能重建工作树与引用
  （`master` / `develop` / tags），使用前用 `git fsck` 与 `rev-parse` 验证完整性。
- 代价是每次动仓库前花几秒钟验证（解析路径、核对条目数、确认目标），换来的是不再丢掉
  整个仓库。
