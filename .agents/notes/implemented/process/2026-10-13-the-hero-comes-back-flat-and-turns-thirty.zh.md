# Agent Note: 首屏回到平面，转 30 度

Status: implemented

## Problem

3D 侧视（`2026-10-13-the-hero-leans-into-3d-after-all.md`）只撑了一轮。下一条
指令把目标姿态整个换掉了：「在正面立的基础上，顺时针旋转 30°」。这不再是绕着
一块立起的屏幕运镜——而是截图平面正对观众，像一张别歪了些的照片那样顺时针偏转。
此前那套透视机制（`perspective`、`rotateY`、`rotateX`）表达的东西已经不对了：
它在一个用户要正着看的画面上做前缩。

## Decision

**回到 2D 旋转——正是上一篇笔记否掉的那个原语——但否定的理由已经不成立，所以
那条否定不随行。** 当初反对 2D `rotate()` 是因为它做不出纵深；而这次纵深恰恰是
明确不要的东西。`rotate(30deg)` 就是需求本身。CSS 正角度即顺时针，上一轮要的
「左边高、右边低」自动保持。

两处机制值得记下：

- **旋转不改布局盒，改的是绘制盒。** 一张 1.67:1 的图转 30° 后包围盒约为原宽的
  1.17 倍；按右栏 `width: 100%` 摆放会顶出列外，压进间隙、文案和页边距。所以在
  同一个 transform 上叠一层 `scale(.82)`（`rotate(30deg) scale(.82)`）把绘制盒
  收回列内。角度仍是精确的 30°——scale 不碰角度。
- **这台机器上 390px 的截图会说谎。** Windows 强制约 500px 的最小窗宽，
  `--window-size=390` 实际按 ~511 排版再裁到 390 出图——文字看着被裁边，其实
  什么都没溢出。诚实的验证是 iframe 具：一个真实 375px 的内联视口（扣掉滚动条
  之后），在那里 `scrollWidth == clientWidth`，且没有任何元素的变换后包围矩形
  越过边缘。

窄屏在 860px 以下保持 `rotate(30deg) scale(.8)`——角度相同、理由相同，全宽列
下 scale 留的余量略多些。

## Testing

- Headless Chrome 1280×900：图面正对观众，30° 左高右低，完整收在右栏内；文案
  与胶囊行未受影响。
- 真实 375px 视口的 iframe 具：无横向可滚动溢出，没有任何元素包围矩形出界。
  早前那张「被裁切」的 390px 截图已判定为上面的最小窗宽假象，不是回归。
- 深色主题共用同一几何，只有描边色不同。未重拍。

## Alternatives considered

**保留 3D 并叠加 Z 轴旋转（在 `rotateY` 之上加 `rotateZ(30deg)`）。** 否：
那是「侧视、顺便再拧一下」，不是「正面、转 30°」。它保住了字重发虚的代价，
却不再给出用户点名的姿态。

**去掉 scale，让四个角压进间隙和页边距。** 现阶段否：约 39px 的图会压进 32px
的间隙并越过分区边缘，观感更像渲染事故而非意图。若用户要更大，诚实的修法是
加宽图栏，不是放任溢出。

**调 `perspective-origin` 伪装正对。** 否：透视总在某个方向上前缩；
「正面」与「透视」是矛盾，不是旋钮。

## Consequences

**换来。** 精确得到所求姿态：干净、锐利、正对观众的一屏，顺时针偏转 30°。
截图里的字重获完全的清晰——上一轮接受的发虚代价就此退回。

**放弃。** 「立着、从侧边看」的纵深感再次消失，且是明确指令。3D 篇的
「放弃 / 欠着」记录就此成为历史，本篇取而代之。`.hero__art` 上的
`perspective` 与 `perspective-origin` 一并删除，不留死配置。

**欠着。** 与此前相同：下次发布或手动触发 `pages.yml` 之前不上线。无 Dart
改动，六道门禁依构造不变。
