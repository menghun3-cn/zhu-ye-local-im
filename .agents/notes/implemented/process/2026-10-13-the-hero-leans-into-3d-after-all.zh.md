# Agent Note: 首屏截图最终还是上了 3D

Status: implemented

## Problem

双栏首屏落地（`2026-10-13-the-hero-finally-shows-the-thing.md`）没几个小时，
倾斜就错了两次。先是读成左低右高，翻成顺时针修好之后，追问说出了平面旋转
永远给不了的东西：截图要像一块**立起来的**屏幕、从侧边看。2D `rotate()` 是
桌上转过一张纸 —— 没有纵深，角度怎么调都读不出「竖着的显示器」。

## Decision

**把 2D 旋转换成真透视，按图片自己的方式来。**

- `.hero__art` 加 `perspective: 1100px; perspective-origin: 80% 50%`；img 用
  `transform: rotateY(20deg) rotateX(3deg)`（860px 以下 12°/2°）。灭点偏向
  外侧，于是屏幕近的那一侧 —— 阅读开始的设备列表 —— 是清楚的一侧，远侧
  像被略微转开的显示器那样退下去。
- **此前「不用 3D」的理由被推翻 —— 推翻它的是它的用户，而不是被遗忘。**
  那篇笔记拒绝透视是因为三维变换会发虚界面里的字，而清晰正是这张图存在的
  理由。用户已经看过平面版、仍然要纵深；发虚是他们选的代价。那个理由从来
  没错过，只是被压过去了。
- `rotateY` 会让绘制宽度**变窄**（×角度的余弦），所以 32px 栏距和区块
  padding 仍然吃得住投影、什么都不会溢出 —— 这是验过的，不是想当然。
- 窄屏用 12° 保持同一种读法：文案下面放一张纯平截图，会像另一个更寡淡的
  页面。

## Testing

- 无头 Chrome，1280×900 浅色与 390×1400 窄屏。两处都读作从左前方看的竖直
  屏幕；不撞文案、无横向溢出，下方的胶囊行没被动到。
- 深色与浅色共用同一套几何 —— 只有边框颜色不同 —— 上一篇笔记已验过，没有
  重截。

## Alternatives considered

**保留 2D 旋转、只加大角度。** 拒绝：缺的不是角度，是维度。任何平面旋转都
产生不了透视缩短，而「立起来、从侧边看」说的正是透视缩短。

**样机式合成图（屏幕边框、支架、影子层）。** 暂时拒绝：那意味着去**画**
而不是去**展示**真界面，而且每次真实 UI 改动都会让它过期。用户以后要是想
要字面意义的厚度，那是新素材的事，不是一个变换的事。

**更大的透视（更近的灭点、>25°）。** 拒绝：过了 20° 左右，远侧的字就完全
读不了，这张图剩下的职责 —— 展示这个界面 —— 也就没了。

## Consequences

**买到。** 首屏读作房间里一台立着的显示器，而不是一张贴图；需求被满足，
图片本身一个字节没动。

**放弃。** 截图里的字被投影弄虚了，这在用户改主意之前是永久状态。CSS 里
那段解释「为什么本站拒绝 3D」的注释删掉了；这篇笔记接替它成为记录。

**欠着。** 和之前一样：下次发布或手动跑 `pages.yml` 之前什么都不上线。
没碰 Dart，六道门禁按构造不变；format 和 analyze 照跑了一遍。
