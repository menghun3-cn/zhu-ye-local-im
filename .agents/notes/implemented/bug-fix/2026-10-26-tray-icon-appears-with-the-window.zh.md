# Agent Note: 托盘图标与窗口同时出现

Status: implemented

[English](2026-10-26-tray-icon-appears-with-the-window.md) | 中文

## Problem

托盘图标只在窗口第一次被关闭按钮隐藏时才添加。应用还显示在任务栏里时没有托盘
图标，而托盘又是唯一提供「退出」的地方。用户能看到窗口在任务栏上，却看不到任何
退出程序的入口，这个不一致读起来就像功能缺失。

## Decision

`HostShell::Attach` 在接管窗口的同时添加托盘图标，而不是等第一次 `WM_CLOSE`。
图标随窗口存在而出现，在窗口可见的整个生命周期里保持，并且关闭按钮隐藏窗口时它
已经在位。`WM_CLOSE` 路径和 `TaskbarCreated` 恢复逻辑都保持不变、照常工作，因为
`AddTrayIcon` 幂等，这两条路径也仍然调用它。

## Testing

这是原生 runner 代码：由构建 Windows 目标以及打包脚本启动构建产物并探测行为来
覆盖。没有任何 Dart 测试能观察到 `Shell_NotifyIcon`。

## Alternatives considered

**保持「关闭才显示托盘」，并在窗口界面里说明托盘的存在。** 否：托盘本来就是退出
入口，窗口里显示不出托盘图标、而唯一退出动作却在托盘里，这是面向用户的缺陷，
不是文档缺口。

**增加一个 Dart 侧开关来决定图标何时出现。** 否：宿主已经知道如何放置图标；为了让
Flutter widget 能请求一个宿主本来就应当做的事而新增接口，只会增加多余的移动部件，
对用户关心的行为没有任何帮助。

## Consequences

- 托盘图标在窗口存在的第一时间就出现。
- 任务栏与通知区域不再对「应用是否在屏幕上」给出互相矛盾的答案。
- 首次启动即可从托盘使用「显示主窗口」和「退出」，而不是必须先关闭窗口一次。
- 最小化到托盘的兜底检查仍然拒绝在图标添加失败时隐藏窗口。
