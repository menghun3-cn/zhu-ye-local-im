# Agent Note: 删除对话从右键菜单开始

Status: implemented

[English](2026-10-27-conversation-delete-starts-in-the-context-menu.md) | 中文

## Problem

右键点击对话列表行时，应用会立即弹出一个破坏性操作的确认对话框。列表行没有
先展示可选择的动作，因此右键后的第一个可见反馈直接变成了「是否删除聊天记录」的
问题。桌面端对话列表应当先打开该行的动作菜单，用户选择删除后才进入二次确认。

## Decision

现在右键或长按对话列表行会弹出一个以手势位置为锚点的上下文菜单。菜单中的
「删除」项再打开第二步：标题为「删除对话？」的 `AlertDialog`，操作为「删除」和
「取消」。选择「取消」不会改变列表行或聊天记录；选择「删除」会清除原先由该行
动作清除的本机聊天记录，并在对端离线且仅因历史记录而留在列表中时移除该行。

打开会话后标题栏三点菜单中的「清空聊天记录」及其文案保持不变。本次改动只调整
列表行动作的选择方式，不合并两个入口。

## Testing

对话 widget 测试使用真实鼠标右键打开列表行菜单，先断言确认框尚未出现，再选择
「删除」、取消一次，然后再次确认删除。测试还通过长按以及删除离线对话（删除后
列表行消失）覆盖同一个菜单流程。

## Alternatives considered

**继续直接打开确认框。** 否：这会跳过用户选择的动作，并让右键本身看起来就像
删除命令。

**在列表行菜单里同时放入「清空聊天记录」和「删除」。** 否：两者执行的都是清除
本机聊天记录，两个文案会暗示应用无法兑现的差异。

**只给右键添加菜单，长按保持原样。** 否：长按是移动端对同一列表行交互的等价
手势，否则两种手势的第一步会不一致。

## Consequences

- 列表行动作在真正删除前多了一个可见的中间步骤。
- 右键和长按都遵循「先菜单、后确认」的同一流程。
- 在任一步取消都会保留对话及其消息。
- 删除仍只清除本机聊天记录，不会遗忘设备。
