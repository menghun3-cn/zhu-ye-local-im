# Agent Note: 窄屏顶栏保留它的菜单

Status: implemented

## Problem

官网顶栏在 860px 以下会把 `.topbar__nav` 整体隐藏（`site/styles.css`）。
这在导航只放页内锚点时无伤大雅——手机读者照样能滚到「功能 / 下载 /
说明」——但同一条导航还承载着「源码」和「联系」下拉，后者是官网唯一的
反馈入口（QQ 群）。在手机上整个入口消失了：用户根本没有办法进群。

## Decision

现在 860px 以下顶栏里多了一个汉堡按钮（`#navMenuBtn`，复用
`.theme-toggle` 的方形样式），与主题切换按钮并排。它点开
`.nav-menu__panel`——样式与 `.nav-drop__panel` 同源的下拉面板——列出与
桌面导航相同的四个入口，外加一个直达 QQ 群的「联系」链接：下拉里本来就
只有这一项，在一个本身就是下拉的菜单里再套一层没有意义。

整个 `.nav-menu` 子树在断点以上是 `display: none`，桌面顶栏不受影响；
断点以下 `.nav-menu` 取 `margin-left: auto`，正好占住被隐藏导航让出的
位置。`site/app.js` 给菜单与「联系」下拉相同的契约：点外面、Esc、点任意
链接都会收起，`aria-expanded` 跟随状态。

## Alternatives considered

**保留导航可见，让它换行或横向滚动。** 否：五个入口加一个下拉塞不进手机
顶栏，而横向滚动恰恰会把窄屏最需要够到的那几个藏起来。

**移动端只显示「联系」一项。** 否：它补上了报告的缺口，却让「源码」依旧
不可达，还凭空造出第二种形状不同的导航，要和第一种并行维护。

**把「联系」挪进页脚。** 作为唯一修法被否：页脚已经有「源码 / 发布记录 /
更新日志」，而联系是主动作不是版权页脚——把它埋起来与它当初放在顶栏的
理由相悖。

## Consequences

- 手机读者多点一下就能到达所有导航目的地，包括 QQ 群；桌面端的标记与
  行为完全不变。
- 菜单在 `index.html` 里复述了一遍导航链接清单，将来改导航要同步改
  `#navMenuPanel`——与页脚链接清单本就接受的代价相同。
- 面板相对 `.nav-menu` 定位、位于吸顶顶栏内部，覆盖页面内容而不撑动版
  面；`z-index` 继承顶栏的 20。
