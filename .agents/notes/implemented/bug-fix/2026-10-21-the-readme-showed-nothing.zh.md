# Agent Note：README 什么都没显示

Status: implemented

[English](2026-10-21-the-readme-showed-nothing.md) | 中文

## Problem

`master` 上的 README 显示出六张坏图，开发段落则像一堵 diff 文本墙。

这份报告背后是两个各自独立的缺陷：

1. **文件本身是坏的。** 提交 `a975b4f`（"docs: update README to Chinese with
   screenshots"）把原始的 patch hunk 追加了进去，而不是写入它本该写的那个文件。
   交上去的是 292 行：一份残缺的 README，然后是六段重复的、以 `N + ` 开头的
   字面文本，前后各来了一遍。两处 shell 代码块用的是单反引号（```` `sh ````），
   所以 Markdown 把它们渲染成行内片段，而不是代码块。
2. **那些图本来就永远加载不出来。** README 指向 `design-preview/_shots/*.png`，
   而 `.gitignore` 忽略了 `design-preview/`。那些文件不在仓库里，所以 GitHub
   给每一张都返回了 404。

第二点有先例：`2026-10-13-the-hero-finally-shows-the-thing.md` 为官网首屏的
同一问题得出过同一个结论 —— 那是**复制**二进制文件到受版本管理的路径，而不是
引用未入 git 的那个。

## Decision

**README 指向受版本管理的图片，而这些图片由一个受版本管理的脚本生成。**

- 图片放在 `docs/screenshots/` —— 会话、设备、剪贴板、传输、设置。该目录入 git，
  所以 `master` 的全新克隆里，README 引用的每一张图都在。
- `tool/screenshots/capture_screenshots.dart` 负责产出它们。它通过既有的
  `test_flutter/support/ui_harness.dart`，用真实的控制器驱动真实的 widget 树，
  因此一张图不可能和它所展示的界面走偏。它是脚本而不是测试：它要写文件，而一个
  每次运行都改写仓库自身文档的测试套件，没人会相信它是绿的。
- 脚本放在 `tool/` 而不是 `test_flutter/`，所以 `flutter test test_flutter`
  不会跑它。真正跑它的门禁，是维护者在界面变化时手动执行的那一条：
  `flutter test tool/screenshots/capture_screenshots.dart`。
- README 的开发段落现在列出仓库真正执行的门禁 —— `test/` 用 `dart test`、
  `test_flutter/` 用 `flutter test test_flutter` —— 而不再是那条既发现不了纯 Dart
  套件、也发现不了 widget 套件的 `flutter test`。
- 损坏的内容已经清除。README 共 58 行：这个项目是什么、五张截图、以及如何构建
  与测试。
- README 的开发段落止于调试构建命令。关于「怎么重新生成这些图」的那一段
  —— 命令本身，以及「这个脚本会改写受版本管理的文档，所以它不是门禁」这番
  解释 —— 被删掉了：那番解释是本笔记的，而命令是脚本自己的文件头注释。
  README 现在共 49 行。

### 这些图画的是什么

截图工具是一套测试架子，而测试架子会**因省略而说谎**，除非把它逼成在两个读者
最容易误读的事实上如实相告：

- **真实的局域网地址，不是回环地址。** 测试里所有 `Device` 共用的那个内存发现 hub
  会把对端报在 `127.0.0.1` 上，因为那正是它说话用的那个套接字所在之处。
  `AddressedBeaconTransport` 把听到的每个数据报重新报在 `192.168.1.115` 上，
  于是图里的地址是一个局域网工具真可能显示出来的地址。
- **一个像样的文件夹，而不是脚手架自己的临时目录。** 否则设置页面上显示的会是
  `C:\Users\admin\AppData\Local\Temp\local-transfer-shot-52ea63b4` —— 那是关于一次
  测试运行的事实，而不是关于这个产品的事实。

图里的设备名、地址与端口都是示例，README 里也是这么说的。

### 这些图是可复现的

一幅每跑一次就换一张的图，没法和它取代的那张对比，所以脚本把本来会变的两个事实
钉死了：

- **身份。** 设备首次启动时铸出一对 Ed25519 密钥，而它的指纹是从那把密钥推出来的
  —— 所以不钉住身份的话，每次截图的指纹都不一样，于是那个 diff 由指纹组成，
  而不是由界面组成。`SeededProfileStore` 给每台设备一颗固定的种子，从它出来的
  指纹就成了截图本身的一个固定事实。
- **端口。** 被告知端口 0 的设备会拿操作系统随手给的那个。截图把四个端口钉在项目
  默认端口区间之上，因为拍这些图的机器上通常正跑着一份这个应用，而它已经占着默认
  的会话端口了 —— 一个套接字不能被绑定两次。

现在脚本连跑两次产出的是逐字节相同的 PNG，这正是这些图能当 diff 来审的原因：
图变了，就是界面变了。

## Testing

- `flutter test tool/screenshots/capture_screenshots.dart` 跑通并写出五张 PNG。
  每张都打开看过：每个界面的中文都是真正的字形，会话里有文字气泡、文件气泡和
  图片气泡，图片气泡里那张图是解出来的，而不是留着一个占位块。
- 连跑两次产出逐字节相同的文件，用 SHA-256 核过。
- 六道门禁全过；README 本身的改动不触及它们。

## Alternatives considered

**引用 `design-preview/_shots/`，并为它加一条 `.gitignore` 例外。** 否决：那个
目录是设计工作区 —— 标注图层、草稿、临时文件 —— 为了拿六张图而把整个工作区
纳入版本管理，等于把工作台的状态放进仓库。官网早就对同一个目录做出过同样的判断。

**从 `design-preview/` 里手工裁出五张图再提交。** 否决的理由与首屏那次「复制而非
引用」相同，还有第二条：裁剪只做一次、此后永不刷新，于是每发一个版本，这些图就
离真实界面更远一点。而驱动真实界面的脚本不会走偏。

**把截图脚本留在 `test_flutter/` 里当测试。** 否决：它每次运行都会往仓库里写五张
PNG，于是每跑一次 `flutter test test_flutter` 工作区就变脏，而门禁的红绿状态也
取决于一个副作用。它是脚本，由人手来跑。

**让 README 指向已发布安装包里的截图。** 否决：并没有这样的截图，而为此另造一个
位置，就是多一个需要保持同步的地方。

## Consequences

**换来。** `master` 上的 README 显示出它的图片，开发段落读得通了，而界面一变，
这些图可以用一条命令重新生成。

**让出。** 仓库现在多了五个二进制资产，截图脚本也成了可能变陈旧的东西 —— 改了界面
却不重跑脚本的维护者，发出去的仍是旧界面的图。没有任何机制强制这件事，而 README
现在也不再写怎么重新生成 —— 那条命令在脚本自己的文件头注释里，离真正要跑的那个
脚本隔着一个文件。

**欠着。** 截图依赖 Windows 的字体路径，也依赖一个固定的局域网地址
（`192.168.1.115`）；它只能在跑它的那台机器上跑，在地址不同的机器上，图里的地址
也就不同。
