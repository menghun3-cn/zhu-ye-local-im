# Agent Note: 发现设备后自动连接

Status: implemented

[English](2026-10-23-discovery-connects-automatically.md) | 中文

## Problem

`v0.1.16` 的界面仍要求一个人发起配对，再由另一个人接受请求。这不是产品要求：
发现另一份正在运行的本程序就是连接动作，两台设备必须能直接发送文字、图片、文件和
表情，不需要任何人寻找「配对」按钮或接受弹窗。

用户报告的故障还暴露了同一条路径上的第二个缺陷。设备可能先广播自动发现信息，
随后才绑定自动配对监听端口。监听器启动后，`PeerRegistry` 没有把新广播的
`pairingPort` 当成可见变化，因此设备列表和控制器都收不到通知。PC 因而可能按地址
显示 Android 设备，却把这一行写成不接受连接，而且没有任何操作能修复这个状态。

## Decision

自动发现会建立设备组信任并自动打开会话。界面没有「配对」按钮、配对码、请求弹窗、
接受步骤、应答请求开关或「重新配对」操作。另一台设备一旦可见，自动交换完成后，
用户就可以直接发送文字、图片、文件和表情。

* `PeerRegistry.observe` 把 `pairingPort` 的变化视为可见变化。信任监听器就绪时，
  控制器会重新收到这台设备。
* 自动发现到设备组外的对端时，程序自动开始现有的开放配对交换。对端已在组内、
  但暂时没有广播会话监听端口时也走同一流程，因此还能恢复「名单仍在、组密钥丢失」
  的 profile。
* 只有 Fingerprint 较小的一端发起自动配对。两端都能从已有事实算出同一顺序，
  新设备不会同时生成两个互不相关的组密钥。
* 接收端控制器自动准入并确认每个有效的发现请求。`PairingRequest` 和
  `PairingAttempt` 仍保留为协议接缝；应用层不再把请求转交给界面。
* 两个已有设备组通过开放配对相遇且组密钥冲突时，双方都选择 Fingerprint 较小
  一端的密钥。手输码兜底路径仍拒绝冲突密钥，因为它保留了带外校验，不能静默合并。
* 控制器串行提交配对。两个并发的发现握手都会基于最新 profile 合并名单，不会互相
  覆盖。
* 发起配对的一端拨出第一条会话。自动配对进行期间，重连扫描不会同时拨向该对端；
  握手结束后才由扫描补试另一个方向。这样不会建立两条互相判为重复的会话。
* 自动配对和会话拨号失败后使用有上限的退避，并由现有扫描重试，不弹出打断用户的
  模态窗口。

文件接收仍是每次传输都要确认的决定，剪贴板共享仍是逐设备显式选择。两者都独立于
设备组成员关系：自动连接只让设备可达，不代表对方可以写入文件或替换剪贴板。

手动地址仍只用于设备已经属于同一设备组、但自动发现不到时的排查连接。它是兜底
路径，不是另一套准入流程。

[陈旧的设备组成员关系通过重新配对恢复](2026-10-22-stale-group-membership-repairs-by-pairing-again.zh.md)
已被本决策取代。此前引入点击配对、常驻请求监听器和一键接受弹窗的笔记仍保留协议
理由，但不再描述当前用户流程。

## Alternatives considered

**保留一次性的「配对」与「接受」流程。** 否决：这正是用户报告的产品错误。局域网里
已经可见的设备，应当无需另一个人在另一块屏幕上操作就能使用。

**两台设备都发现对方时都发起配对。** 否决：两台新设备会在并发握手中各自生成组
密钥。按 Fingerprint 排序可以让双方在没有额外往返的情况下得到同一个发起端。

**配对后两端都拨出第一条会话。** 否决：重复会话可能互相关闭，最后两端保留不同
连接，或者都没有可用会话。由发起配对的一端拨号，扫描负责补足可达方向。

**手输码路径也按同一规则解决组密钥冲突。** 否决：这条路径有带外码，可以安全地
拒绝意外合并。静默选择胜者会削弱这个带外校验的含义。

**只为陈旧名单保留「重新配对」。** 否决：发现流程可以恢复缺失的密钥，再暴露一个
准入入口就违背了自动连接规则。

**不把自动配对端口纳入可见变化比较。** 否决：这正是让「先广播、后启动监听器」
的设备卡死的缺陷。可拨号目标变化必须产生发现事件。

## Consequences

- 同一局域网内两台运行中的设备会自动进入一个设备组并打开会话，不需要用户准入。
  该网络中任何可达的本程序副本都能加入设备组，因此产品以可信局域网和操作系统
  网络边界为前提。
- 监听器启动顺序与自动发现不一致时，首次连接更可靠；单边陈旧名单无需手动修复。
- 设备组成员关系沿用合并规则。两个已有设备组相遇时，Fingerprint 较小一端的组
  密钥成为共同的组密钥。
- 对话列表仍显示自动发现的设备，只对「已知组成员、端口可拨但暂时断开」保留
  「连接」作为重试；不会提供「配对」或「重新配对」。
- 设备页和设置页报告自动连接是否就绪，不再提供应答配对请求的偏好。
- `test/discovery/peer_registry_test.dart` 锁定自动配对端口变化事件。
  `test/app/app_controller_test.dart` 覆盖自动发现、同时发现、陈旧密钥恢复、文字
  与表情送达以及会话拨号归属。组件测试和双窗口测试断言没有弹窗或配对控件，信任
  与会话仍会自动出现。
