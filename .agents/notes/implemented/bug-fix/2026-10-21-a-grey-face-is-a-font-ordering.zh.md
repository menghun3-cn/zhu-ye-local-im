# Agent Note: 灰掉的表情是一个字体顺序

Status: implemented

[English](2026-10-21-a-grey-face-is-a-font-ordering.md) | 中文

## Problem

表情面板变灰了。

不是全灰 —— 那些本来就是象形符号的脸还留着颜色，而用户会叫作「那些符号」的
变成了平的：举起的手、叉号、对勾、问号、星星、闪电。一个灰色轮廓的表情面板，
和前一个版本画成彩色的同一个面板摆在一起，看起来像个渲染 bug，
却没有人指得出问题出在哪：这个仓库里没有一行写错，日志里没有异常，
颜色也没有被设成黑色以外的东西。

原因是一份列表里的一个条目。

主题的字体回退链，是那些中文字体没有的字符最终被画出来的途径。
它原本有三个条目，后来有了第四个：`Segoe UI Symbol`，
加进来是为了给输入框的 `☺` 按钮一个字形 —— 中文字体里没有 `☺`，
没有一张符号脸，那个按钮就是个空框。这是个真问题，这个修法也对。

但它同时无声无息地终结了这个应用里的颜色。

`Segoe UI Symbol` 是一张**单色**符号脸，而它装着全部表情码点的单色轮廓。
这台机器上还有 `Segoe UI Emoji`，它画的是同一批码点，但是彩色的，
靠的是 COLR 彩色层。两张脸都声称拥有这些码点，于是链上的**顺序**决定谁赢 ——
而链是按顺序查的，先命中先赢。单色那张脸在前面。

于是每一个没有单色轮廓可退的象形符号仍是彩色的，而每一个单色脸**确实**有轮廓的
码点都变成了灰色轮廓。变灰的脸，恰好就是单色脸覆盖的那批脸。
面板、表情表、气泡都没有变 —— 变的是一个字体顺序。

弄坏它的那个提交讲的完全是另一件事：README 的截图，
以及截图里那些掉到平台默认字体上的标签。它把符号脸加进链里，
作为一次字体修复的最后一步，颜色跟着一起没了。
`v0.1.11` 的链有三个条目，表情是彩色的；`v0.1.12` 的链有四个，表情是灰的。

## Decision

**彩色那张脸排在单色那张脸前面。**

`Segoe UI Emoji` 现在排在 `WeChat.fontFamilyFallback` 里
`Segoe UI Symbol` 的前面。符号脸留在链上 ——
它是输入框 `☺` 按钮的字形来源，也是那些箭头和数学符号的来源，
而那些字符别的脸都没有 —— 但它现在只画彩色脸没有字形的东西。

这就是全部修复，而且只是把一个元素换了位置。链在其余方面本来就是对的；
它只在一件事上错了，而那件事正是彩色与灰色之间的差别。

**关于表情本身，有两件事被钉住了。**

*Unicode 默认是文字呈现的码点要带上变体选择符 U+FE0F。*
光一个 `✋` 是单色轮廓，因为 Unicode 默认这么说；`✋️` 才是举起的手。
`❓` `❗` `⭐` `⚡` 同理。表里有四张脸带着文字呈现，现在都带上了选择符。
`✌️`、`❤️`、`☀️` 本来就有。

*表里的每一张脸都有可画的彩色字形。* 任何已安装的彩色字体都不覆盖的码点
会画成空框，而顺序救不了它 —— 只能换掉这张脸。有一张就是这么换的：
`🫡`（敬礼的脸）在这台机器的任何字体里都不存在，换成了 `🙌`（举手），
相关的字体都画得出彩色。

**表情表用的就是主题的字体。** 表情格子自己没有点名任何字族，
所以它继承主题的链 —— 顺序就住在那里。有一处显式点了名：
输入框按钮上的 `☺`，它要的是主题的字族和主题的链，而不是平台默认。

## Alternatives considered

**在面板自己用一张字体画表情，链不动。**
否决：同样的脸在另外三个地方被画 —— 输入框、气泡、最近使用条 ——
每一处都得各抄一份规则。而链本来就是唯一一处说明
「这台机器怎么画这个应用没有的字符」的地方，
缺陷正在于那一个答案是错的。在三处修就会把第四处留在错的状态。

**把符号脸从链上撤掉，给 `☺` 按钮单独一张字体。**
否决：链不只是为表情按钮存在的。箭头、数学符号、制表符 ——
它们都是中文字体没有、而平台默认字体也未必有的字符。
撤掉这张脸会修好颜色，同时毁掉当初加它要解决的那件事。

**把表情当图片发，而不是当码点。**
否决：表情表用码点是刻意的 —— 码点是关于 Unicode 的事实，
由接收方平台来渲染，所以两个构建不必就一张脸达成像素一致。
位图意味着要为六十一张脸准备、版本化并授权一套图片，
还会改变线上传的是什么。

**把灰掉的脸换成别的码点 —— 删掉 `✋`，改用 `🖐️`。**
否决：这是治症状。这些脸没有错，错的是它们的画法。
换码点来绕开一个字体顺序问题，等于丢掉用户真正会去按的那张脸
（举起的手就是举起的手），而且顺序对下一个加进来的东西仍然是错的。

**把灰掉的脸换成别的码点 —— 只动表情表。**
否决，而 `🫡` 恰恰就是这么处理的：**没有任何字体能画**的脸必须去掉，
因为没有什么东西可以排序。灰掉那些脸是有字形的 —— 有彩色的字形，
只不过链没有先去找它。

## Consequences

- **脸又是彩色的了**，而原因就在 diff 里：链是这么写的。
- **链的顺序现在是正确性要求，不再是偏好。** 一条测试断言彩色那张脸排在前面，
  因为将来一次「顺手整理一下回退列表」的提交会无声地把它放回去。
- **没有彩色字形的脸在构建期就被抓住。** 那条测试读系统的彩色字体，
  逐个检查表里的脸都有彩色层；没有的会按名字报出来。
  这个检查被验证过：把 `🫡` 放回去，它失败了，而且点名了那张脸。
- **检查读的是这台机器的字体，所以字体不在时它跳过。**
  一台没有 `Segoe UI Emoji` 的机器回答不了这个问题，
  而跳过的答案是诚实的 —— 在那里失败会让套件依赖机器而不是依赖代码。
- **解析器住在 `test/` 下，不在 `lib/` 里。**
  发布出去的应用里没有任何地方问「这张脸是不是彩色的」；
  应用只是把码点交给链，链来定。
  把一个字体解析器放进包里，是为一个没人问的问题增加重量。
- **换了码点的脸在线上也是换了的。** `🫡` 和 `🙌` 是不同的字符，
  所以对端最近使用条里存着 `🫡` 的，匹配不上 `🙌`。
  最近使用条会丢掉当前表情表里没有的脸，这本来就是它对
  「一个不再提供的版本里存下来的脸」做的事。
