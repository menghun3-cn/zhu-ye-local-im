# Agent Note: 补录 0.1.38–0.1.39 更新日志条目

Status: implemented

[English](2026-11-06-backfill-changelog-0.1.38-0.1.39.md) | 中文

## Problem

`dart test` 在 develop 上失败：`changelog_entries_test.dart` 报
`0.1.38` 与 `0.1.39` 两个条目没有覆盖其版本区间内的全部用户可见
提交。同一个红色背后是两种不同的缺口：

* `0.1.38` 的截图提交其实**已经**被中文 bullet 描述，但测试的
  英译中词表缺 `screenshot`、`overlay` 等词，匹配器看不到这条
  提及。
* `0.1.39` 则是真漏了两个提交——文档对齐提交和「我的」页接收文件
  夹统计修复——没有任何 bullet 覆盖。

## Decision

**补录缺失 bullet，扩充词表。** `0.1.39` 条目按提交原意补了两条：
修复栏加接收文件夹计数一条，变更栏加 README/官网/安装包文档对齐一
条。测试的 `translated` 词表补入已发布条目实际使用的高频功能词——
`screenshot`/`screenshots`→截图、`overlay`→遮罩、`hotkey`→快捷键、
`navigation`→导航、`card`→卡片、`folder`→文件夹、`incoming`→接收、
`settings`→设置——沿用 `0.1.36` 条目上次扩充词表的同一机制。

## Consequences

* `dart test` 在 develop 上恢复全绿；门禁没有变钝——词表只是对更新
  日志已在用的词变得更精确，并没有放宽「什么算提及」。
* GitHub Release 正文与应用内更新面板里 `0.1.38`/`0.1.39` 的说明现
  在讲全了这两个版本的全部内容，这本来就是条目的本职。
* 已发布条目仍可为这类遗漏而编辑——`0.1.36` 当年补录
  `0.1.30`–`0.1.32` 时定下的先例。改写条目的**含义**依然禁止，补
  全它不在此列。

## Alternatives considered

**放宽匹配器。** 否决：问题不在匹配器太严——有两个提交确实没有
bullet，而一个分不清「已用中文描述」与「根本没提」的匹配器，正是
这个测试要堵的缺口，而不是要扩大它。

**保持发布时的原样。** 否决：条目就是 GitHub Release 正文和应用内
更新面板展示的内容；漏掉的改动等于用户从未被告知，这正是该测试
要抓的缺陷本身。
