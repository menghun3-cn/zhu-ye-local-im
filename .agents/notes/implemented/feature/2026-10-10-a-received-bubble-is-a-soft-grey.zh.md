# Agent Note: 接收气泡是一档浅灰，气泡里的轨道取气泡自己的墨色

Status: implemented

## Problem

上一轮重绘（`2026-10-10-two-greens-one-scale-and-a-white-received-bubble.md`）把接收气泡挪到了
会话底板那块白上，再给它一圈发丝线，好让它至少能被看见。那是一对自洽的数字，却是一件不自洽
的东西：浅色下底板就是白的，于是一条收到的消息是一个用 `#E7E9EE` 勾出来的白色矩形。在真实
窗口里看（而不是在色卡上看），一条自己没有填充的消息读起来像是「给人围出来一个空框」，而不是
一件「到了的东西」。

上一份笔记反对灰气泡，反对的是**页面底灰**——那正是气泡当时披着的那层别名。那个值确实读起来像
一个禁用控件。而仅仅比面板低一档的灰不会，两者此前被当成了同一个选项。

改填充之后又翻出第二个早就在那的问题。传输气泡里那条进度条把轨道画成 `surfaceSunken`，而在浅
色调色板里那**恰好**就是接收气泡的填充，于是轨道会在气泡里消失。顺手去深色调色板里查同样的
错，查到了：`surfaceSunken`（`#20252E`）与 `bubbleIn`（`#21262F`）只差一档，也就是说从进度条
重绘那天起，深色下接收气泡里的轨道就是看不见的。没有任何门禁抓到它——测试当时能断言的只是
**某个 widget 用了某个令牌**，而不是那个令牌与它落上去的表面不同。

## Decision

**接收气泡取面板的「凹陷一档」。** 浅色调色板里 `bubbleIn` 是 `#F0F1F4`，正是 `surfaceSunken`
与 `listHover` 已经在用的值——于是这个角色的含义是「比面板低一档」，底板保留它的白。发丝线留
着，但它不再承重。两个主题之间共享的是**职责**而不是方向：白纸上气泡比底板暗一档，深色纸上比
底板亮一档。

**进度条的轨道取气泡自己的墨色，降透明度。** 即 `WeChat.progressTrackAlpha`（0.16）乘上
`bubbleText` 或 `bubbleOutText`，按气泡方向选。轨道要落在四种填充上——两个主题 × 收/发两种
气泡——没有任何一个调色板颜色与这四者都保持固定距离。从墨色派生，轨道与气泡之间就恒是一个固定
距离，而新增的测试钉的正是这条性质。

**裸图片那条轨道继续用 `surfaceSunken`。** 它画在会话底板上而不是气泡里，在底板上那就是正确的
一档。所以两条轨道不同，且是刻意的：规则是「轨道必须与它落上去的东西差一档」，而不是「两处调用
点必须命名同一个颜色」。

## Alternatives considered

**保留白气泡，靠发丝线**。否。那就是已经发出去的版本，它在窗口里就是一个勾出来的空框。一个像素
的线足够分开表格里相邻的两块填充，不足够让一条消息读起来像一条消息。

**用页面底灰 `#F4F5F7`。** 否。那正是上一份笔记否掉的别名，重新取用它等于把上一条测试防的那层
关系搬回来——气泡与页面共用一个值。它还会让气泡回到 `pageBackground` 的一档之内，而那是应用里
**其他所有**页面的底色。

**轨道用 `divider`。** 否。它是一个看似合理的固定色，但它不是一个固定距离：压在浅色气泡上约
ΔRGB 8，压在深色气泡上约 6——盯着看能看见，动起来就看不见——而同一个值在两种绿上又很强。它只会
对四种填充里的两种是对的。

**给气泡单独一个灰，某个既不是这也不是那的值。** 否。调色板之所以是调色板，就在于它的值是复用的。
`surfaceSunken` 的含义已经是「比面板低一档」，而这里恰恰就是那个；再造一个第四种近白十六进制来
说同一件事，是一套调色板开始散架的方式。

## Consequences

**`bubbleIn` 下游的一切重绘，其余不动。** 气泡的填充、发丝线的职责、气泡内轨道的颜色。没有布局、
没有尺寸、没有文案、没有线路改动。

**`shell_test.dart` 里两条断言必须反向。** 一条钉着 `bubbleIn == conversationBackground`，另一
条钉着浅色气泡的亮度**等于**底板。现在两条都钉相反的关系——填充不同，方向按各自主题所需——并且
前者额外钉住气泡不是 `pageBackground`，那个被否掉的别名因此无法悄悄回来。

**现在有一条测试守的是轨道，而不是令牌。** 它把墨色按 `progressTrackAlpha` 分别合成到四种填充
上，要求亮度差，于是断言针对的是**结果**，换掉墨色或换掉透明度都仍然成立。它本可以抓到的那个
深色缺陷，此前一直在发。

**`#F0F1F4` 够不够灰是个眼睛问题。** 和上一轮重绘一样，分析器和测试都回答不了；如果答案是不够，
那是一个令牌的事。
