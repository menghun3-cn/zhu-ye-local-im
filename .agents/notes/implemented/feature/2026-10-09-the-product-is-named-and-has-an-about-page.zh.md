# Agent Note: 产品有了名字，也有了一个「关于」页

Status: implemented

## Problem

`local_transfer` 是一句描述，不是一个名字。它要送到用户眼前有三处，且都得靠人手动保持一致
—— Flutter 外壳渲染的那个串（`l10n.appTitle`）、在 `windows/runner/main.cpp` 里创建的
Windows 窗口标题、以及 `windows/runner/Runner.rc` 里可执行文件的 `FileDescription` 与
`ProductName` —— 外加打包用的说明文件。要求是给它一个自己的名字：竹叶局域网传输。改名这件事
的完成度，永远取决于它最不显眼的那份拷贝，所以这次的活儿是**把拷贝找齐**，而不是写出那个串。

外壳还带着一条不做事的 `AppBar`。它把应用名**又写了一遍**，而窗口自己的标题栏早就在显示它；
它旁边还放着本设备的名字、平台图标和一枚「未配对」标记。这三样都不是「正在看的这个页面」的
事实，而是**本设备**的事实 —— 而设备页早就把每一样都说了，还说得更细，就在隔壁一个标签页。
一条重复窗口标题、又重复另一个页面内容的栏，是一条可以去掉的栏。

还有一处没人回答的问题是「我现在跑的是哪个版本，怎么拿到更新的」。这个程序没有更新器，也不打
算长出一个 —— 它不带后端，承诺就待在局域网里 —— 但一个从同事手里接过一个 zip 的人，对版本
有合理的疑问，而应用里没有任何东西回答它。

## Decision

**名字放在平台会读到的地方，别的任何地方都不再自己造一个。** `l10n.appTitle` 两种语言都持
竹叶局域网传输（`appTitle` 是专有名词，不翻译），runner 的窗口标题与资源串持同样的字，
说明文件也以它开头。可执行文件的**文件名**仍叫 `local_transfer.exe`：除了去文件夹里翻的人，
它并不面向用户，而打包脚本和它的冒烟测试都以这个名为准，改它什么也换不来，只会弄坏那个证明包
能用的流水线。

**`AppBar` 是去掉，不是裁剪。** 诱惑是留着这条栏、只砍掉三样里的一样，但每一样要么是窗口标题
的重复、要么是设备页的重复，所以没有东西可留。没有 `AppBar` 之后，正文就是整个窗口 —— 这也
正是六个页面想要的：每个页面本来就画了自己的 `SectionHeader`，在第一个标题上面再来一条标题
行，就是多了一条。只为这条栏的 tooltip 而存在的 `notPairedYet` 串也随它删掉。

**「关于」是它自己的一个页面，不是设置里的一个区块。** 它是唯一一个主题是**程序本身**、
而不是本设备或本网络的页面，也是唯一一个会跟外面世界说话的页面，所以它最不该被折进
「收到的文件放哪」旁边。它成为导航栏上的第六个目的地，排在设置之后。

**在用户按下「检查更新」之前，什么都不离开这台机器。** 页面显示版本号（`appVersion`，一个
常量，由一条测试盯着它和 `pubspec.yaml` 不漂移）和一段手动升级的说明 —— 那段话在完全没有网
的时候也成立。只有那个按钮会去问 GitHub，且只在被按下时问 —— 不在启动时，不在定时器上。
一个全部主张就是「待在局域网里」的应用，绝不能在一打开某个页面时就悄悄往 GitHub 开一条 socket。

**更新的问题问的是仓库，而每个答案都是一个名词。** `GitHubUpdateChecker` 去问
`api.github.com/repos/menghun3-cn/zhu-ye-local-im/releases/latest`。它得到的答案是
`upToDate`、`available`、`noRelease`、`unreachable` 之一 —— 四个名字，不是一句话，因为把
结果变成文字，属于「知道读者读什么语言」的那一层。`noRelease` 与 `unreachable` 分开留着，是
因为它们是要告诉人的两件不同的事：「还没有任何已发布的版本可供比较」与「这个问题没能问出去」，
把人引向不同的地方。

## Alternatives considered

**用 `package_info_plus` 从平台读版本号。** 这是了解一个构建版本号的常规办法，而它是一个
**原生**插件注册，只为读回源码里本来就有的一个串。`appVersion` 是
`lib/app/app_version.dart` 里的一个常量，`test/app/app_version_test.dart` 会读
`pubspec.yaml`，两者一漂移就让构建失败 —— 这恰好就是那个插件能买到的一切，还不带原生依赖。

**用 `url_launcher` 打开下载页。** 同一个取舍：为一个调用买一个原生注册。`openInBrowser`
改问 Windows 自己的 shell（`cmd /c start "" <url>`），并且在地址靠近 shell 之前，拒绝一切
不是 `github.com` 上 `https` 地址的东西 —— 地址通常来自 GitHub 的响应，但 shell 就是 shell，
这道检查正是用来拦住一个被构造出来的地址被读成后续命令的。

**自动下载并安装新版本。** 这是要求最大的那种版本，被否掉了：写一个安装器并启动它，是一项
原生的、平台相关的、安全敏感的能力，而这个程序没有签名方案。关于页把链接交给用户；安装，仍然
是人来做的事。

**把「未配对」做成一角的小标记，而不是整条栏。** 这会保住那条栏唯一一个别处没那么响的信号。
它输给了两件事：设备页本来就把配对状态说得明明白白；以及一条栏的代价 —— 一整条常驻的窗口，
用来放一个一辈子变两次的事实。

**把更新结果在 checker 里就拼成句子。** 部件更少。否掉，是因为 checker 在树里不碰 Flutter 的
那一半、不该知道语言；把结果变成用户的话，是 `labels.dart` 里 `describeUpdateCheck` 的活。

## Consequences

应用名现在是两种语言下的专有名词，所以 `appTitle` 不再是译者该动的东西，说明文件与窗口标题也
跟它一致了。

现在是六个页面作为 `IndexedStack` 的孩子，而不是五个，导航栏（宽窗的 rail 与窄窗的 bar）都多
出一个目的地；任何断言过「五个页面」或列举过标签名的地方，都更新成了六个。

`AboutPage` 是唯一一个持有网络状态的页面，也是唯一一个在请求在外时按钮会失效的页面。
`UpdateResolution.checker` 是一个可变缝，形状照抄 `PickerResolution`，于是 widget 测试能在
没有 socket 的情况下把页面的每个分支都走一遍 —— 包括 `available` —— 而 `UpdateResolution.reset`
在 `tearDown` 里恢复真 checker。

一个出不去的构建，现在有一个会如实告诉你的按钮，而不是一个会卡的页面：checker 自己的超时是
八秒，它把每一种失败 —— 超时、DNS、代理拒绝 `CONNECT` —— 都变成 `unreachable`，因为到底是哪个
异常，从不改变该拿它怎么办。

## Testing

`test/app/app_version_test.dart` 读 `pubspec.yaml`，断言 `appVersion` 与它的 `version:` 一致
（丢掉构建号），于是显示的版本不可能与文件被构建成的那个版本漂移；它还把 `isNewerVersion` 钉在
带前导 `v`、带 `-rc` 后缀、以及缺一段的情形上。

`test_flutter/ui/about_page_test.dart` 通过 `UpdateResolution` 装一个 `_StubUpdateChecker`，
把页面在每个结果下都驱动一遍。它断言按下按钮之前什么都不问（stub 记录了它被调用过）、
`available` 会露出下载链接和它的地址、`noRelease` 与 `unreachable` 各自产出自己那句话、
以及那段升级说明在每个状态下都在屏幕上。

`test_flutter/ui/shell_test.dart` 断言外壳在六个页面上方**没有** `AppBar`，断言应用名不再作为
外框被渲染，同时本设备的名字仍能在设备页上够到 —— 这正是「栏走了，事实留下」的两半。它的导航
标签用例现在列的是六个页面，关于在其中。
