# Agent Note: What a newer version says it changes

Status: implemented

[English](2026-10-13-what-a-newer-version-says-it-changes.md) | 中文

## Problem

「关于」页能说出**存在**一个更新的版本——「有新版本 v0.1.2。」——却说不出版本里有什么。而发布自己的说明一直就在手上：`release.yml` 把该版本的 `CHANGELOG.md` 那一节作为 Release 说明发布，于是 `parseRelease` 为了找 `tag_name` 与 `assets` 而读的那份回答里，本来就带着这些变更，只是没有一个字段去看它。

结果就是：卡片在请用户做一个决定，却没有说出这个决定所依赖的任何东西。那句话旁边的按钮——「下载并更新」——会替换本程序所在的整个目录并重启它。版本号回答的是「这是不是更新的」；它回答不了「值不值得为此打断我手上的事」，而站在那个按钮前面的人，真正有的正是后一个问题。用户本可以打开下载页去浏览器里读说明，而浏览器很可能正是这台机器上唯一连不上 GitHub 的地方——那条缺陷记在另一条笔记里。

还有两件更小的事实指向同一个方向。这次检查已经为说明付过费了：它就在同一份回答里。而现有四种结果本来就已经各用一句话说细节——「已是最新版本。」与「有新版本 v…。」是两句不同的话——所以这张卡片早就已经是那个把答案讲清楚的地方；缺的只是对读者重要的那一部分。

## Decision

**说明在进来的路上被原样携带，不被解释。** `UpdateCheck.notes` 装发布说过的话，只有在结果为 `available` 且说明不是空白时才不是 null：

```dart
notes: body is String && body.trim().isNotEmpty ? body : null,
```

取 null 而不是 `''`，是为了让界面只需要问一个问题。只有空白字符也算 null，理由相同——一段全是空行的说明就是一个无话可说的发布，而一张为了展示「什么都没有」而打开面板的卡片，是在宣称有新闻。

**`lib/ui/update_notes.dart` 把 markdown 读成「种类是数据」的行。** `UpdateNoteKind` 只有 `heading`、`item`、`text`，`readUpdateNotes` 返回这些行的列表。它不导入任何东西——不导入 Flutter，也不导入本地化——这正是
`test/ui/update_notes_test.dart` 能在 `dart test` 里覆盖它的原因，那是唯一一道总能跑的门禁。

这个读法里有三个值得点名的决定：

- **折行的句子被接回去。** `CHANGELOG.md` 的一条是手工在八十列左右折行的，所以一句话常常是三个源码行。当成三行展示，读者读到的就是作者的换行，而不是「改了什么」。续行靠缩进辨认，且只在某条条目之下——空行、小标题或新的条目都会终结上一条。
- **折行吞掉的那个空格，只在它本来就该有的地方补回来。** 中文句子在两个汉字之间断开，接回去不补空格（「取回新包、」接「按发布方…」）；而 ASCII 词之后的断行要补（`sha256` 接「核一遍」是 `sha256 核一遍`）。规则就是拿断口两侧各和 `0x80` 比一次，而发布说明里的两种情况都有。
- **标记本身消失。** `###`、`**`、反引号、链接的地址，都是读者没打过、也不需要的东西：小标题按小标题画，重音按正文画，`[发布说明](https://…)` 画成「发布说明」。

**卡片在版本那句话下面画一个带标签的面板，而且只在有东西可放时才画。** 标签（`l10n.aboutUpdateNotes`，即「更新日志」）之所以在，是因为这个面板是一段**引文**——发布方自己的话——而在一张其余部分都是本程序自己口吻的卡片里，一段没有出处的引文会被读成本程序对自己的断言。底色取 `surfaceSunken`，这正是本设计给「内嵌面板」的那一档，它同时也让一份十来行的更新日志不至于被读成卡片正文的一部分。小节靠字重而不是字号区分——更小会读成脚注，更大则会和上面那句版本号争。条目的正文挂在圆点**旁边**而不是下面，这样折行的条目不会读成自己的子条目。

**没有引入任何依赖。** 这里没有 markdown 渲染器，而本程序将收到的全部 markdown，就是它自己的发布流水线写出来的那一种。

## Alternatives considered

**正经渲染 markdown，引入一个包。** 否决：为了一个页面上的一个面板，要引入一个渲染器、一项依赖和一条需要跟的版本线——而渲染器还会带来这张卡片永远不会见到的许多 markdown（表格、图片、代码块、脚注）。这里之所以知道形状，是因为这个仓库自己在发布它；而这个形状需要的读法只有四十行。

**把说明原样画出来。** 否决：读者第一眼看到的就是 `### 新增` 和 `**应用内一键更新**`，那是发布的文件格式，不是发布的新闻。上面「接回」与「去掉标记」两个决定，都是因为卡片不是文件查看器。

**保留作者的换行，每个源码行各画一行。** 否决：那是最简单的读法，而它会在作者写了一句的地方给读者三行短短的、参差的行。这个接回法唯一的真实代价就是那条空格启发式，而它在两个方向上都测到了。

**把说明放到别处——一个对话框，或者单独一页。** 否决：面板属于做决定的地方。按钮、版本号、地址都已经在这张卡片上；为了搞清「要不要这个东西」而把读者送到另一个界面，是在为一个段落安排一次往返。

**从构建自带的文件里读 changelog。** 两条理由都否决它：安装好的构建并不带 `CHANGELOG.md`——`packaging/` 只随包发布使用说明——而且它读到的那一节描述的是**正在运行**的那个版本，恰恰是这张卡片上唯一不需要问用户意见的版本。

**给面板限高、让它自己滚。** 否决：那是页面自身列表里的嵌套滚动区，滚轮与拖动都要另作论证，而它省下的只是一段十来行、页面本来就可以更高的内容。

**只在该版本是里程碑（第二位号变动）时才显示说明。** 否决：提出它并不认真——本产品的版本号里，没有任何一种读法能让补丁版的变更比次版本的不值得读，而且发布流水线在说明里也不区分二者。

## Consequences

- **卡片回答了它自己发出的那个邀请。** 「检查更新」现在通向版本号、改了什么，然后是两种据此行事的方式。
- **「关于」卡片变高了，而且它的高度此后取决于发布。** 整份说明都会被画出来；页面滚动，什么也不截断——某个版本的说明写得很长，那就是一张很长的卡片，而不是一张藏东西的卡片。`UpdateNoteKind` 保证它不至于成为一团混沌：小标题按小标题排版，条目按条目排，而不是一整面文字墙。
- **`UpdateCheck` 多了一个字段，两条分支都被覆盖。** 「关于」页的测试对一份带说明的发布断言了面板及其中四行文字，也对一份没有说明的发布断言只显示版本号、连标签都不出现。
- **说明是 GitHub 回答的引文，没有任何东西去核对它。** 它旁边的校验值是拿来核那个到手的文件的；说明不属于任何这类核对，也不可能属于。它是按发布写下的样子渲染的——这也正是那个去标记的读法必须**对**、而不必**聪明**的原因。
- **用 `--generate-notes` 发布的版本读起来是另一个样子。** GitHub 自己的生成器会写下「What's Changed」和若干条目，再加一行 `**Full Changelog**`；它会以一个小标题、若干条目和一段正文的形式到达，诚实且可读，只是不是任何人写的句子。
- **`update_notes.dart` 是第三个知道「发布长什么样」的东西**，排在 `release.yml` 与 `CHANGELOG.md` 之后。它是三者中唯一**读**这个格式而不是写它的，也是唯一一个其输入不归本仓库管的。
