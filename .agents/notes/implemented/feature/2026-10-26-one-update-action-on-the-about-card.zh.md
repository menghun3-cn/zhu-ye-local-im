# Agent Note: 关于页只有一个更新操作

Status: implemented

[English](2026-10-26-one-update-action-on-the-about-card.md) | 中文

部分取代[左侧菜单更新按钮改为一键安装并在 About 页进行](2026-10-15-the-rail-entry-installs-instead-of-opening-a-browser.md)：
旧笔记在关于页留下了「检查更新」和安装两个按钮。左侧菜单入口、安装流程、
确认框和忙碌状态上报仍然有效。

## Problem

关于页同时显示「检查更新」，并在发现新版本后再显示一个实心的「下载并更新」
或「下载并安装」。两个按钮都是同一张卡上的主操作，用户必须先理解第一个按钮的
答案决定第二个按钮是否存在；而这个相同的用户动作还按平台用了两个名字。

第二个按钮在下载期间也需要明确不可用。若它置灰时旁边的「检查更新」仍然可点，
卡片看起来就像安装正在进行时还有另一件事可以做。

## Decision

卡片只在同一位置保留一个实心主操作：

- 还不知道有可安装的新版本时显示 `Check for updates`，中文为「检查更新」。
- 检查进行中显示「正在检查…」并禁用。
- 发现新版本且当前平台支持应用内安装后显示 `Update`，中文为「更新」。
- 下载、校验、解压或交接期间仍显示「更新」但禁用；进度文案单独说明当前阶段。
- 失败或用户取消确认后再次显示可点击的「更新」。已准备好的包直接复用；安装
  入口本身也会在 `_busy` 时拒绝调用。

Windows 与 Android 共用 `aboutUpdate` 文案，英文为 "Update"。平台相关的提示和
确认文案继续说明是重启程序还是打开系统安装器。

平台不支持应用内安装时，发现新版本不会把主操作改成「更新」；卡片保留
「检查更新」，并继续提供次要的手动下载页入口。

## Alternatives considered

**保留两个主按钮。** 这把卡片本可以替用户排好的两步决定又交还给用户，而且安装
进行中仍会留下一个「检查更新」按钮。

**始终把按钮叫做「更新」。** 这会在尚未检查时声称已有更新，也会移除唯一明确的
询问入口。

**执行期间把文案改成「正在下载」。** 进度条和阶段文案已经说明了这一点。保持
稳定的「更新」文案，把正在发生的事交给禁用状态和进度报告。

**按平台使用不同的动作文案。** Windows 与 Android 启动的是同一个用户动作，只是
启动后的安装方式不同。共用文案让主要决定保持一致。

## Consequences

- 卡片只有一个实心操作；`aboutCheckForUpdates` 和 `aboutUpdate` 是同一个控件的
  互斥状态。
- 有可安装更新等待处理时，用户不能再运行一次检查。失败或取消确认后可以重试
  更新。
- 次要的「打开下载页」保持不变，并在检查或更新期间禁用。
- `_install` 独立于禁用按钮，在 `_busy` 时拒绝调用，因此两个入口不能在第一帧
  禁用状态绘制前启动两次下载。

## Testing

`test_flutter/ui/about_page_test.dart` 守住按钮切换、无更新状态、下载期间禁用、
禁止重复点击、失败后重试、取消确认后复用已下载包、Android 安装器流程，以及
不支持应用内安装时的回退。
