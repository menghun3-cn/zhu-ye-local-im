# Agent Note: 配对改为点击式，不再输码

Status: implemented

[English](2026-09-30-click-to-pair-no-more-typing.md) | 中文

## Problem

打包出来的应用第一次真机试用就撞上了：Join 对话框要求填地址、端口和一个
十位配对码，结果码被贴进了地址栏。错误提示——`that is not a Pairing code:
a pairing code is 10 symbols, got 0`——既准确又毫无用处。从一个屏幕上抄码、
到另一个屏幕上敲进去，恰恰是人最容易出错的环节，而这条流程在事情能开始之前
就要用户填三个字段。

输码的意义在于往配对握手里放一个秘密。但输码路径本来就被定位为兜底方案——
`PairingSecret` 自己的类注释就说明 50 位的码是攻击者可以离线穷举的上限——
而真正守着准入关口的是两块屏幕各自显示、双方各自确认的六位短认证串。这个
应用也早就自动发现了链路上的每一台设备，只是发现列表一直没提供「和发现的
设备配对」的入口。

## Decision

配对改为两次点击，界面上不再有输码环节。

这两次点击中「应答」的那一侧，已经不再是一个窗口：它是一个常驻监听，加上
「每次来电都要过一道人」的准入闸门。这套机制、以及窗口为什么被换掉，由
[常驻应答配对请求](2026-09-30-pairing-requests-instead-of-a-window.zh.md)
负责；本笔记负责的是「配对改为点击式」这个决定本身，以及随之而来的密钥规则。

* 接收方**应答配对请求**（`PairingService.receive`），只要档案里的设置允许，
  它就一直在公认配对端口上监听，并对每一个来电方逐一询问自己的用户。
* 发起方在发现的设备卡片上点 **Pair**，走 `joinOpen(host: peer.address)`——
  不需要知道端口，因为目的地就是对端的公认配对端口，而且刻意不用本机自己
  绑定的端口。这个调用要等到对方用户放行之后才会返回。
* 两块屏幕仍然显示六位数，双方用户仍然要确认。这一步守着「准入是人的决定」，
  而在握手秘密公开之后，它就是配对与链路上第三个设备之间**唯一**的防线。

这个公开常量绝不能派生出群组密钥。开放配对时，应答方改为**读完对端的准入
消息之后**再决定自己发什么：自己已有群组密钥就发自己的；对端带来了就什么
都不发（新设备加入既有群组）；两边都是全新的就现场铸造一个随机密钥发过去。
于是两个互不相关的全新配对不共享任何密钥材料——若从常量派生，全球所有新
配对会被放进同一个隐式群组。输码路径保持从码派生密钥，与之前完全一致，这
也是应答方「先读后发」的重排要靠 `openPairing` 区分的原因。

六位数确认之后，发起方自己开 Session（`connectAfterPairing`），并有界地
重试。重试是必须的，因为第一次拨号可以正当地失败两次：对端的 beacon 还没
重新广播新 Session 层监听的端口，而发起方自己的 discovery 在描述符变化后
重启、注册表还是空的。每次重试都会重新解析目标，所以下一条广播一到 Session
就开了，不需要用户再点一次。

## Alternatives considered

**保留输码，改用二维码或共享剪贴板自动填充。** 否决：第三、四个字段和第二
块屏幕照样存在，而且未配对设备的剪贴板是本地的——不存在一条能搬运配对码、
又不预设配对已经完成的信道。

**从公开常量派生群组密钥。** 直接否决：那会让握手秘密和 Session 秘密成为
同一个值，任何完成过开放配对的设备都持有同一把 Session 密钥。应答方现场
铸造的规则只花了一次消息顺序调整，就让两个秘密再无关联。

**开放路径取消六位数比对。** 否决：握手秘密公开之后，这六位数不是第二层
保密——它就是全部的校验。去掉它，配对就变成「谁先来谁进」。

**用「让应答方为它开一个窗口」来限制开放配对可以发生的时机。** 这条先上线
过，后来被替换：见
[常驻应答配对请求](2026-09-30-pairing-requests-instead-of-a-window.zh.md)。

## Consequences

- 两台设备配对变成：一边在设备卡片上点 Pair，另一边应答自动弹出的请求，核对
  六位数，确认。没有输入框，没有转抄，没有地址，两边都不需要事先准备什么。
- 链路上的设备现在可以**发起**开放配对，以前它无法主动发起输码配对。确认
  步骤是补偿控制；输码路径保留在核心层，留给未来的二维码或带外流程，而它在
  `lib/ui` 里已经没有入口，测试脚手架的状态搭建也不再走它，改走请求路径。
- `pairing_service_test.dart` 钉住了密钥规则：开放配对双方商定同一个新鲜
  密钥、两个独立的开放配对不共享密钥、新设备加入既有群组会采纳该群组的
  密钥。
- 双窗口 E2E 测试现在走的就是人会点的那些按钮，而且 Session 由 guest 自己
  打开——发文件的断言跑在一条没人手动拨过的 Session 上。
