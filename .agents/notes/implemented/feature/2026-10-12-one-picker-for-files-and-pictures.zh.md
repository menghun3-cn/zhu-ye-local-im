# Agent Note：文件和图片共用一个选择器

Status: implemented

## Problem

输入框原本有两个附件控件：一个写着「发送文件」的回形针，一个写着「发送图片」的图片图标。它们为同一个意图打开了两个不同的对话框，而第二个是对第一个的谎报。

`SystemPicker.files()` 调的 `openFiles` 完全不带过滤；`image()` 调的 `openFile` 带 `acceptedTypeGroups: [XTypeGroup(extensions: imageExtensions)]`。但那道过滤是第二个控件**唯一**改变的东西。选中的东西究竟算什么，从来不由控件决定：两条路都汇进 `_stagePaths`，它用 `looksLikeImage` 逐个分类，再交给 `_sendMessage` —— 图片走 `sendImage`，其它走 `sendFile`。也就是说回形针本来就能发图片，而且一直在发；一件事有两个控件，其中一个还在用标签教会用户一条代码里并不存在的规则。

真正让这件事不只是「不够整洁」的是那个标签。「发送文件」读起来就是「文件，不包括图片」，而这条信念恰恰是本产品不能制造的：一条消息算图片还是算文件，决定的是**对方要不要被问一句**（`_landingFor`：图片按配置目录到达即落盘；文件要等人点一下），而一个学会了「图片走另一个按钮」的用户，学到的是**按钮在决定类型**。按钮不决定，从来没有决定过 —— 决定的是扩展名。两个入口等于请用户把一条关于界面的规则，当成一条关于文件的规则记住。

## Decision

**一个控件，一个对话框。** composer 留下回形针，tooltip 仍是 `menuSendFile`，第二个控件删掉。`SystemPicker` 只留一个方法 —— 不过滤、可多选的 `openFiles` —— `image()` 删掉；它实现的 `FilePicker` 缝同样。`ScriptedPicker` 测试替身也失掉它的第二条队列，而这正是重点：测试从此再也表达不出「这是通过图片按钮选的」，因为那个按钮不存在了。它只能表达用户真正做的事 —— 把一张 `.png` 放进选择结果里 —— 剩下的交给 `looksLikeImage` 回答。

**类型仍然是对文件的读法，不是对界面的读法。** 没有任何东西搬进 composer：`classifyPaths` 与 `looksLikeImage` 未动，到达规则（`_landingFor`）未动。图片仍然到达即画、不用任何人应答；文件仍然等人点一下。这次合并本该在行为上不可见 —— 如果它改变了这两半里的任何一半，那就是合错了。

**那个控件当年画过的图标还在包里。** `Icons.image_outlined`（0xf120）保留在打包脚本的 `$requiredGlyphs` 里：`labels.dart` 的 `iconForKind` 会在每一个标出消息类型的列表上画它，画不出来的图片所用的占位也用它。改的只是注释 —— 它当初进包的那个理由（那个控件）没了。

**那句死文案跟着走了。** `menuSendImage` 再没有调用点，tree-shaker 会正确地把它从 `app.so` 里去掉 —— 这正是打包探针 `'发送图片'` 必须在同一次改动里删掉的原因。一句再也够不到的探针，就是在**正确的包**上永远红灯；这个项目上过一次当（`chooseFolderTitle`）。这个 key 从两个 `.arb` 和三个生成文件里都删掉了，手工保持一致，因为本机跑不了 `gen-l10n`。

## Testing

`test_flutter/ui/pages_test.dart`。原来那条「通过图片控件选一张图」的测试，现在通过附件控件来选 —— `picker.willOffer([source.path])`，里面是一张 `.png` —— 并断言 `filesAsked == 1`，所以「只有一个对话框」这件事由测试本身钉住。

第二条是新增的，也是这次改动真正关于的那条：**一个对话框能分别按各自的方式发出图片和文件。** 一次 `willOffer([picture.path, note.path])`（多选对话框交回结果的形状），然后：Alice 的两条 transfer 是 `[image, file]`；Bob 那边的图片已经落盘（`localPath != null`）且没人回答过任何东西、也从未出现在 `offers` 里，而文件不在磁盘上、是唯一在等一次点击的东西。这条测试从头到尾没有问过「按的是哪个控件」，因为改动之后只有一个。

`test_flutter/support/ui_harness.dart` 跟着它对应的选择器方法一起失掉 `imageButton()`、`willOfferImage()` 与 `imagesAsked`。

## Alternatives considered

**保留两个控件，把图片那个当成过滤器。** 否决：错的就是那道过滤。它没有改变消息的任何东西，所以只可能误导 —— 而且确实误导了，它宣称了一条「`发送文件` 发不了图片」的规则，而代码里并不成立。把它留作「快捷方式」等于留着那句谎，还多给一条通往同一个对话框的路。

**给合并后的对话框加一个图片的 `XTypeGroup`**，让它的文件类型下拉里有「图片 / 所有文件」。否决：这等于在对话框里把同一个暗示再讲一遍，而且它拿默认视图做代价 —— 而绝大多数选择都发生在默认视图里。一个因为过滤而打开就是一份子集的列表，比一个打开就是全部的东西更糟。

**把 tooltip 改成「发送文件或图片」。** 否决：「发送文件」本来就是这个意思（这个工具一直用它在发图片），而且可见 diff 越小越好 —— 改一个字符串就是打包探针必须跟着学的一句话，而现在这句在 harness 与端到端测试里是按名字断言的。

**在缝里留着没人用的 `FilePicker.image()`。** 否决：这条缝存在的意义是替身平台，而一个没人调的方法，它的测试替身也没人驱动。删掉它，才是让测试替身无法谎报图片是「怎么」被选中的。

## Consequences

**换来的。** 一个意图、一个控件、一个对话框。标签现在描述了控件真正做的事。而真正决定一条消息类型的规则 —— 扩展名 —— 只在一个地方写着（`looksLikeImage`），不再由两个各带一种过滤的控件暗示两遍。

**随包文档跟着动了。** `packaging/使用说明.txt` 有三处在描述那个不复存在的控件（输入框那一行、「发图片：两种方式」那一节、以及第一次配对的走一遍）；三处现在都写成同一个回形针，并说明是扩展名在区分图片与文件。

**删了一条打包探针，改写了一条字形注释。** `$newProbes` 去掉 `'发送图片'`；`$requiredGlyphs` 保留 `0xf120` 并写明它为什么还在。没有新增 —— 这次改动没有往 `app_zh.arb` 里加任何句子，这句值得说清楚，因为 `$newProbes` 是一份「必改清单」。

**两条 widget 测试从未跑过。** 写这段的机器上 `flutter test test_flutter` 起不来 —— `Process.start` 的管道 stdio 报 `CreateFile failed 231`，把整条工具链一起带走。这里的推理来自源码：分类看 `classifyPaths` 与 `looksLikeImage`，到达规则看 `_landingFor`，每个暂存附件走哪条路看 `_sendMessage`。工具链正常的机器上仍然欠一次绿灯。
