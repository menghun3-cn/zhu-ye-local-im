# Agent Note: 设备、传输与对话控件放在使用它们的地方

Status: implemented

[English](2026-10-23-device-transfer-chat-ux.md) | 中文

## Problem

应用已经具备局域网传输需要的事实和动作，但没有总是把它们放在用户能找到的地方。

设备页描述了监听状态，却没有说明对端应该使用哪个本机地址。新身份被命名为
`unamed device`，即使操作系统已经有主机名。设置页重复展示了同一份本机信息，
而且两个存放位置画法不同：身份路径是一段文本，接收目录却是可编辑输入框。

其余问题集中在用户反复使用的工作流。更新频率控件在窄屏 Android 窗口中会被截断。
已完成文件传输没有直接打开所在目录的入口。窗口隐藏时，新消息可能未读，但任务栏
没有任何提示。对话列表不能搜索，打开的对话也没有明确的清空入口。最后，Android
可以检查并下载更新，但关于页没有把已校验 APK 交给系统安装器的操作。

## Decision

**身份信息可见，并且从主机名开始。** 设备页的本机卡片在监听行上方显示所有非回环
IPv4 地址，以 ` · ` 分隔；地址枚举失败时显示不可用状态。该卡片继续负责本机别名、
指纹、平台、设备组、会话和监听状态。

`loadOrGenerateLocalProfile` 为新生成的身份使用 `Platform.localHostname`。它会
迁移一次已经保存的 `unamed device` 别名，而且只在本机名可用时这样做。其他已保存
别名都视为用户决定，不会因为之后的操作系统改名而被覆盖。

**设置页只保留一份事实。** 重复的本机卡片被删除。剩下的存放位置包含两个同形输入框：
身份文件只读并带锁图标，接收目录可编辑并带选择目录按钮。身份字段仍可选择和复制，
但不能在输入框里编辑。

**更新频率改为滚动而不是截断。** 四个选项仍然是 `SegmentedButton`，外层使用横向
`SingleChildScrollView`。这样保留原有控件和选中状态，同时给 360 像素宽的 Android
窗口足够空间。

**已完成传输直接提供所在目录。** 只有传输完成且路径可打开时，卡片才显示
`folder_open_outlined` 按钮。原有右键菜单保留，所以这个图标是额外快捷入口，而不是
替代品。

**未读是窗口状态，而不是另一个应用内角标。**
`LocalTransferController` 暴露 `totalUnread`；`HomeShell` 把它和原生窗口活动流
结合，再调用 `HostShell.setUnread` 接缝。Windows 通过 `ITaskbarList3` 绘制红色
任务栏覆盖图标，并在 `WM_ACTIVATE` 中先于 Dart 往返清除它。Dart 也跟踪同一激活
事实，避免两侧对“窗口是否正在被查看”产生分歧。

**对话搜索过滤列表，而不是过滤历史。** 搜索框以不区分大小写的方式匹配对端显示名、
消息文本和附件名。命中的消息会成为行预览，因此结果能说明为什么匹配。空搜索保持
正常列表；非空搜索无结果时显示专门空状态。

**清空对话需要明确确认，并且只影响本机。** 三点菜单由紧凑和完整对话头共享。它保留
原有信任操作，并增加“清空聊天记录”，点击后二次确认。清空会删除该对端的非剪贴板
消息、忘记已读水位，并把进行中的对话传输标记为已忽略，避免迟到完成重新显示记录。
剪贴板历史独立存在，不会被清空。

**Android 更新最终交给系统安装器。** `PlatformUpdateInstaller` 现在有 Android 路径：
选择发布 APK，要求发布方 SHA-256，下载到应用私有的 `update` 目录，校验后调用
Android 方法通道。Runner 用非导出的 `FileProvider` 暴露该目录，检查
`canRequestPackageInstalls()`；缺少权限时打开本应用的未知应用来源设置，否则以读取
授权启动系统安装器。关于页为 Android 切换文案和错误提示，不再承诺重启进程。

## Alternatives considered

**猜测一个本机地址，或只公布监听使用的地址。** 否决：一台机器可能同时有 Wi-Fi、
有线和 VPN 地址，猜测对端可路由的地址会把缺失事实变成错误事实。卡片展示操作系统
报告的全部地址。

**每次启动都用主机名覆盖别名。** 否决：用户输入的名称是一个决定，仅因为机器改名就
在未告知的情况下改变对端看到的设备名，是不可接受的。只迁移旧的自动占位名称。

**为了可发现性，在设置页保留重复的本机卡片。** 否决：两张卡片会争抢同一组事实，
并且可能逐渐不一致。用户需要身份和监听状态的位置是设备页；设置页只保留存放位置和
应用设置。

**身份路径继续用普通事实行，只把可编辑目录画成输入框。** 否决：用户正在比较两个
存放位置，同形布局让比较更容易。锁图标已经说明差异，不需要让身份路径看起来像另一类
信息。

**在 Android 上让频率选项换行，或替换成下拉框。** 否决：换行会把一个控件拆到多行，
下拉框会隐藏可选值。横向滚动能保持分段控件完整。

**让整张已完成卡片都打开目录。** 否决：卡片还承载选择和详情，大点击区会让误触菜单
或危险操作更容易。专用尾部图标既直接又没有歧义。

**未读提示完全留在 Flutter。** 否决：窗口隐藏时 widget 无法修改原生任务栏图标。
控制器继续拥有未读计数，宿主负责呈现。

**只清除对话当前可见的消息。** 否决：对话由持久化历史支撑，只清 UI 会让旧消息在下次
加载时重新出现。持久化的非剪贴板记录和已读水位必须一起删除。

**通过浏览器或普通文件 URL 打开下载的 APK。** 否决：Android 要求为系统安装器提供
content URI 授权，普通 file URI 会被平台的文件 URI 限制拦截。FileProvider 和原生
通道才是受支持的路径。

## Consequences

- 设备页会告诉用户在另一台机器上输入什么地址，包括多个网络接口；无法读取时会明确
  显示不可用。
- 新身份无需先改名就能辨认；已有自动生成身份只迁移一次，自定义名称保持稳定。
- 设置页减少重复，两个存放位置可以直接比较。
- 更新频率在窄屏 Android 上仍然可用。
- 已完成的传输可以一键到达所在目录。
- Windows 在窗口隐藏时可以提示未读，并在用户激活窗口时立即清除提示。
- 对话搜索可以找到已经不是该行最新消息的文字或附件。
- 清空对话不可撤销，也不会声称删除磁盘文件或剪贴板记录。
- Android 更新安装依赖用户授予未知应用来源权限，并依赖系统安装器可用；两种失败都有
  明确且可操作的提示。
- `test/` 覆盖纯 Dart 的配置、阅读状态、控制器和安装器行为。
  `test_flutter/ui/pages_test.dart`、`about_page_test.dart` 和
  `unread_badge_test.dart` 覆盖界面和任务栏接缝。Android 方法通道名称与
  FileProvider 契约由平台桥接测试检查。
