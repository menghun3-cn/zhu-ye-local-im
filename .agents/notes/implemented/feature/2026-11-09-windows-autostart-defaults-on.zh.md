# Agent Note: 开机自启对新设备默认开启

Status: implemented

## Problem

「开机自启」这个开关的存在意义，是让一台本该随时可被触达的设备不必在每次重启后手动启动 ——
但它出厂是关的，于是每一次新安装都得先找到开关才可被触达。需求是把它改成默认开。

朴素的修法 —— 「profile 从没被碰过就写注册表」—— 分不清新装和「用户亲手关掉了」的存量安
装：从外面看两者一模一样，因为「关」就是 `Run` 里没有条目。把默认值追溯性地打开，会悄悄
把每一个选择过关的用户重新打开自启。

## Decision

`DeviceProfile` 新增 `autostartPreference`，一个三态值，记录「这个选择是否已经做过」：未决
定、开、关。它随 profile JSON 持久化；在该字段出现之前写下的 profile 解码为未决定。

默认值落在 `AppController.start()`，也只在那里。在 profile 加载之后、在有 `HostShell` 的
平台上：

- 若偏好是未决定**且**这个 profile 在本次启动前并不存在 —— 真正的新设备 —— 跑一次
  `setAutostart(true)`：宿主写入条目，偏好记录为开。
- 若偏好是未决定但 profile 已经存在 —— 早于默认值的安装 —— 读出当前注册表状态并记录为
  使用者的答案，不写任何东西。机器上原本怎样，它就继续怎样。
- 一旦偏好是开或关，启动就不再碰条目。注册表仍然是「实际会发生什么」的权威；偏好只回答
  「有没有人选过」。

`setAutostart` 在宿主写入之后把使用者的答案记进 profile，因此一次明确的「关」在之后每次
启动都保持。「profile 在此之前是否存在」靠在 `loadOrGenerateLocalProfile` 之前先做一次
`ProfileStore.load()` 判定，因为那个调用会把新 profile 当副作用创建并保存。

整块逻辑形状是 Windows 的，但代码平台无关：Android 没有 `controlsWindow`，它的
`hostShell` 会回答 `MissingPluginException`，而现有的 `PlatformHostShell` 处理本来就把它
当作「什么也没发生」。需要已决定偏好的测试由 `ui_harness.dart` 里 `ScriptedHostShell` 的
默认值提供，因此 widget 测试不会悄悄继承新默认值。

## 这次明确不做的事

不从安装包写注册表。绿色包根本没有安装器，而且安装器写入的条目会和应用内开关打架：应用读
到「开」而 profile 说未决定，第一次启动就会记录一个使用者从没做过的选择。

也不记自启的*状态* —— 只记是否选过。条目本身仍在每次启动时被读回来，所以亲手删掉条目的
使用者看到的开关依然汇报实际会发生什么。

## Alternatives considered

**把「注册表里没有条目」当作「新装」。** 否决：「未配置」和「亲手关掉」无法区分。这正是偏
好存在的全部理由。

**升级时对所有人默认开一次。** 按决定否决：存量安装保持原样。想要自启的用户早就打开了；
关掉过的用户保持关；只有真正的新设备拿到新默认值。

**让宿主层拥有默认值。** 否决：宿主同样分不清第一次启动和回访启动，而且「问过没有」这个
事实属于使用者选择，应该和 `CloseBehaviour` 一起放在 profile 里。

**存解析后的状态而不是三态。** 否决：缓存「开」或「关」就是操作系统所拥有事实的第二份
副本 —— [桌面宿主层](2026-10-12-the-desktop-host-shell.zh.md)里被否决的那条依然成立。
三态只记录「选过没有」，从不记录操作系统在做什么。

## Consequences

**换来的。** 新的 Windows 安装在重启后无需访问设置即可被触达；存量安装不受影响；任何方向
的明确选择都是永久的；开关汇报的仍是注册表的真相，而不是一份缓存副本。

**profile 格式多了一个字段。** 旧 JSON 解码为未决定，对「写于此字段出现之前」是正确答
案 —— 启动逻辑随后记录当前状态而不写入。向前兼容不变：更新版本的取值是未知字符串，按宽
容方式解码。

**启动多一次 store 读取。** `start()` 现在在生成 profile 之前先读一次，以判断它是否已存
在。常见路径上这是一次小 JSON 读取。

## Testing

`test/profile/device_profile_test.dart` 覆盖该字段：默认未决定、旧 JSON 缺键、开/关的往
返，以及 wire 名。

`test_flutter/ui/window_settings_test.dart` 用 `ScriptedHostShell` 覆盖行为：新设备被默认
写入一次且下次启动不再重复；早于默认值的安装记录宿主已有的状态而不写入；关掉开关再重启
保持关。
