# Agent Note: 未读数，以及回到上次那个对话

Status: implemented

## 问题

一次报上来七个问题，五个是外观、两个不是。

那五个外观问题其实是同一个缺陷换了五顶帽子：控件被要求「能多小就多小」。主题在两个按钮
主题上设了 `minimumSize: Size.zero`、`tapTargetSize: shrinkWrap`、`visualDensity:
compact`，输入框主题上设了 `border: InputBorder.none` 配 `isDense: true`。结果就是：一个
「检查更新」是一行扁平的绿字而不是按钮；对话框底部的动作只有两三厘米高；地址输入框在
一块几乎同色的面板上没有一条边，读起来像一个「有标签的空白」而不是一个能打字的地方。

两个不是外观的：

1. **没有任何东西知道「读没读过」。** `MessageRecord` 只记说了什么；
   `LocalTransferController` 里没有「用户看过其中哪一条」这个概念。所以对话列表没法说
   「你不在的时候来了东西」，唯一的办法是一个一个对话点开看。

2. **进对话菜单永远落在一块空白上。** `_selected` 初值是 null，宽窗口那一支就把
   `conversationPickOne` 画在那儿——于是每次回到这个页面，用户都得把同一个对话再点一遍。
   列表旁边杵着一块空白面板的聊天软件，是在让用户重答一道他已经答过的题。

第二个里面还藏着一个更小的：气泡正文是 `Text`，**刻意**不可选中，因为可选的正文会把
右键从消息自己的菜单那里抢走。于是右键菜单里有一条「复制文字」，复制的是**整条**消息
——而拖过三个字的人要的从来不是这个。

## 决定

### 标准尺寸的控件

`WeChat` 新增一组标准度量——`buttonHeight`（36）、`buttonHPadding`（16）、`fieldHeight`
（44）、`fieldHPadding`（12）、`fieldVPadding`（10）、`composerControl`（40）——主题里
两个按钮主题和 `inputDecorationTheme` 都由它们构成。

- `TextButton` 和 `FilledButton` 现在一样高，因为两者在对话框底部并肩站着，一行两个不同
  高度的按钮看起来是坏的。真正属于**行内**的动作——对话列表的行内按钮、气泡自己的应答、
  发送按钮——一律在**自己的调用点**覆盖掉这几个度量，而不是指望主题是小号的。
- 每个输入框都有真正的描边，用 `borderStrong`，聚焦时换成更粗的品牌色线。唯一不要描边的
  是会话输入框：它套在一层填充里，那层填充**就是**它的边框；它在自己的调用点把六个边框
  槽位全关掉、把约束清零。
- 「检查更新」变成 `FilledButton.icon`，也就是应用里其他所有主操作早就在穿的样式；
  「打开下载页」保持 `TextButton.icon`，因为它打开的是一个页面，不是在这个窗口里做一件事。

### 未读是水位线，不是计数

`ConversationReading`（`lib/core/history/conversation_reading.dart`）给每个 peer 存一个
时间戳：一切 `at` 比它晚的**入站**消息都算未读。计数需要在每次删除、重发、重启之后都维护
一遍，任何一处对不上就错了；水位线是一个数，拿去和真实存在的消息比一次就有答案。

规则就是桌面客户端那一条，用户期待的全部都在这一句话里：**打开对话即已读，退出不会重新
变未读。** 不向对端发送任何东西——没有已读回执，对端也没有知道的必要。

- `LocalTransferController.unreadCount(peer)` 从 `transfers` 里数，也就是对话画的那份
  列表，所以角标和它下面的消息不可能对不上。剪贴板条目被排除，和别处一致。
- `markConversationOpened(peer)` 在对话被**选中**时调用，不是从对话 widget 自己的
  `build` 里调。「用户正在看它」是关于列表选中状态的事实：shell 用 `IndexedStack` 保住
  每一个页面，所以用户在别的页面时对话仍在重建，那不叫阅读。
- 标记是单调的、写是条件写。倒着走的时钟不能让一个读过的对话重新全部变成未读；而且只有
  真的变了才重写文件——因为调用点在 `build` 里。
- `unreadCount` 以一对中括号的形式走在预览**前面**——`[3] 明天见`——而不是红色角标。
  角标属于头像，放在那里才不会被误读成消息开头几个字；这里它和正文共享一行，中括号就是
  把两者分开的东西。整行也会**更响**：名字转半粗，预览从次级墨色升到正文墨色。

### 上次那个对话，记住它

存在同一个对象、同一个文件里的 `ConversationReading.lastPeer`，因为两者一起写，而一个只有
其一没有其二的文件会被读成两个写者都没打算写的状态。

记住的 peer 是**兜底**，不是覆盖。`_untouched` 只在用户点了某一行、或别处发来请求之前为
真；之后记住的 peer 就不再生效，所以这一次坐下的选择永远不会被更早的一次盖掉。记住的那个
对话在显示它的那一帧被标为已读，和点开的一样。

### 文字可以选中，而菜单仍然是消息的

消息列表包在 `SelectionArea` 里，所以双击取一个词、拖动取一段。`SelectableRegionState`
只有创建它的 widget 够得着——`SelectionArea` 把 key 私有持有、也不提供 `of`——所以用
`MessageSelection` 这个 `InheritedWidget` 把选中的文字从区域里带给菜单。

于是 `TransferContextMenu` 就成了**调和本身**：它既是平台的复制工具栏，又是消息自己的
菜单。有选区时它在「打开所在目录」和「删除」**上面**给一条复制选中文字；整条的「复制文字」
在选区存在时让位，因为「复制这条消息」和「复制这三个字」是两个不同的请求，一个会在两者
之间静默切换的菜单是不可预测的。

## 考虑过的替代方案

**行角上的红色数字角标。** 微信自己就是这么做的，这里否掉是布局原因而不是口味原因：那个
角落第一行已经放着时间、第二行放着动作按钮或状态，而 `_ConversationTile` 把两者都限制在
大约三分之一行宽里。角标要么挤掉其中一个，要么成为抢同一块空间的第三个东西。`[N]` 前缀
不占额外地方、就坐在预览本来在的位置，而且同样因为中括号而无歧义。

**存未读计数而不是水位线。** 一个 peer 一个整数比一个时间戳写得少，但它是错的整数：删除
时要减、到达时要加、打开时要清零，而且在能做这三件事的每一条路径上都得对账。用四个字节
换六处可以出错的地方。

**一个 per-peer 的「读过没有」布尔。** 更便宜，但第二条消息进来时就答不了——那行会说
「未读」，而计数会撒谎。

**从 `ConversationView.build` 里标记已读。** 那是对话真正被画出来的地方，很有诱惑力，
但理由同上：shell 的 `IndexedStack` 每一 tick 都重建每个页面，于是标记会在没人看的对话
上触发，而真正在读的对话在应用坐在别的页面时反而没被标记。

**让 `SelectionArea` 自己把菜单画在文字上。** 库的默认行为，而它恰好在用户最需要的时候
把消息自己的那几行拿走了：右键一条文件消息的文字，会打开一个没有「打开所在文件夹」、也
没有「删除」的复制工具栏。这正是旧的 `Text` 用「不可选中」换掉的那个取舍；这一次文字和
那几行都保住了。

**给每个气泡各包一个 `SelectionArea`。** 选区在气泡边缘断掉，不是拖过两条消息的人要的，
而且会在树里给每条消息都塞一个 `SelectableRegion`。

**加 reading 状态时给会话文件版本号加一。** 信封是加了**一个键**而不是改了某个键的含义，
而它要兼容的那个读法是「读 `messages`、忽略其余」——版本号进位恰好把这件事弄坏。`version`
保持 `1`；它该在某个键的**含义**变了时才动，而不是在多了个键时。

## 测试

`test/history/conversation_reading_test.dart`（新增，纯 Dart）：水位线方向、单调守卫、
`unreadFor` 只数入站消息、`retainOnly` 清理，以及 JSON 往返——包括一个在 `reading` 键
存在之前写下的文件。

`test/history/message_store_test.dart`：信封仍然往返；一个没有 `reading` 键的已存文件读回
来时是空的 reading，而不是抛错或丢掉消息。

`test_flutter/ui/pages_test.dart`：行上的未读前缀、未读行更响的样式、进入页面时打开记住
的对话而不是空白面板、点了别的行之后不被记住的那个盖掉；以及地址对话框的输入框走主题
描边、取消/连接是标准高度的按钮。

`test_flutter/ui/about_page_test.dart`：「检查更新」是 `FilledButton`，「打开下载页」仍然
是 `TextButton`。

`test_flutter/ui/composer_keys_test.dart`：输入框的盒子是 `composerControl` 高、比对话框
里的 `fieldHeight` 矮；发送按钮是填充按钮且不矮于它所在的输入框。

`test_flutter/ui/delete_message_test.dart`：原有的断言不变——调和这件事的全部意义就是让
它们继续成立：「复制文字」和「删除」都还在右键文字消息打开的菜单上。新增一条：正文可以被
选中，且选区存在时菜单给的是「复制」、拿走的是整条「复制文字」、而「删除」不换。

## 后果

- 应用里每个对话框一次性获得更高的按钮和带描边的输入框，这正是意图；按文字驱动的 widget
  测试没受影响，按尺寸测量的都过了。
- 会话输入框是唯一退出新输入框样式的地方，所以以后改 `inputDecorationTheme` 不会影响它。
  这是刻意的——它不是面板上的一个字段，它是频道里的一个字段——但它确实是第二个要看的地方。
- `conversationDisconnected` 现在读作 离线 / "Offline"，而不是 连接已断开 / "Session
  closed"。更短，事实一样：离线 就是用户对一台够不着的设备说的话。
- 窄布局里打开一个对话也会标记已读，从「设备」页走到对话的也一样——每一条显示对话的路都
  终止于 `_open` 或记住兜底那一支，两者都标记。
- 在一条文字消息上、没有选区时右键，仍然给「复制文字」，所以整条复制从不缺席；它只是在
  选区存在时**让开位置**。
