# Agent Note：点「接收」文件直接落盘，不再二次询问

Status: implemented

## Problem

在文件传输请求上点「接收」后，会先弹出第二个对话框——「这些文件保存到哪个
文件夹？」——然后字节才开始动。而它提议的文件夹本来就是本机的接收目录：
输入框里预填的正是 `controller.incomingDirectory ?? defaultIncomingDirectory`，
和图片不问一声就落进去的是同一个值。也就是说，这个对话框收集的是一个设备
早就有的答案，还让「接收」按钮看起来只完成了一半。

这个对话框并非摆设，它有成文的理由，写在 `acceptOffer` 的注释里：
「文件夹是被问出来的而不是假定的，因为一个只会写一个文件夹的设备就是一个
什么都归不了类的设备。」这条论证说的是**没有**文件夹的设备。它完全没提到
有文件夹的设备——而每台 Windows 安装都是这种（平台默认目录总能解析出来）——
在这些设备上它就是纯粹的摩擦。选择文件夹的权利也没有丢：接收目录从
2026-10-09 那一轮起就在设置页里，那才是放文件夹决定的地方。

## Decision

**`acceptOffer` 只在没有文件夹可报的时候才问。** 当传入的 `defaultDirectory`
能解析出来——用户在设置里选的，或平台默认——请求就直接落进去：目录不存在就
创建，然后 `acceptInto`，结束。解析不出来时（某个平台两样都没有），既有的
对话框照旧打开，因为在那里这个问题不是「再确认一遍」，而是给文件夹命名的
唯一途径。

**「什么要等用户回答」的规则原封不动，也仍然只有一个地方说了算**：
`_landingFor` 对文件仍然返回 null，所以文件仍然要用户来答，气泡上仍然画着
接收/拒绝，没有任何东西未经允许就落盘。变的只是回答的代价。图片和被接收的
文件现在走同一条路、进同一个文件夹——这也正是用户会写进需求里的那句话。

对话框的代码和它渲染的所有文案仍被编译、仍从兜底分支可达——那些句子的打包
探针继续通过，探针一条没加也没删。

## Testing

`test_flutter/ui/pages_test.dart` 新增「accepting a file asks no second
question when there is a folder to receive into」：Bob 带着
`defaultIncomingDirectory` 启动，Alice 发一个文件，Bob 在「传输」页点接收，
测试钉住三件事——不弹对话框、Transfer 完成、字节以自己的名字落在那个文件夹
里（按 localPath-晚于-settle 的规则等 `existsSync`）。既有的对话框测试继续
覆盖另一条分支：它的 Bob 启动时没有文件夹，所以问题照样出现，注释也写明了
这正是原因。

## Alternatives considered

**像图片一样到达即收。** 否：这会推翻上一轮有意做的决定——文件就是要用户
来答，「接收」就是同意。去掉的是第二个问题，不是第一个。

**记住对话框上一次答的文件夹。** 否：那是一次一个对话框地重新实现设置项，
而且装机后的第一次传输仍然要问。设置页本来就是选文件夹的地方。

**在已落盘文件的右键菜单里加「另存为」。** 这次不做。它能把对话框过去顺手
提供的「这一次存到别处」还回来，又不挡在点击和字节之间；但它是没被要过的
功能，需求是去掉问题，而且文件夹从同一个菜单的「打开所在目录」已经够得着。

**把对话框整个删掉。** 否：有的平台没有可以假定的文件夹，在那里这个问题
是接收的唯一途径。

## Consequences

**买到。** 一次点击、一次落盘、一个文件夹——和图片同一个，用户可以在设置里
改它，而且只在设置里。

**放弃。** 对话框顺手提供的「这一个存到别处」。如果真被想念，上面那条右键
「另存为」才是正经的回头路。

**新测试从未运行过。** 本机 `flutter test` 起不来（任何带管道的
`Process.start` 都报 `CreateFile failed 231`）；这一跑欠在有一套可用工具链的
机器上，和它旁边那两条驱动对话框的测试一样。
