# Agent Note: 固定在侧栏底部的更新入口

Status: implemented

## Problem

这个程序知道有新版本，却谁也不告诉。唯一能问出答案的地方是「关于」页，而且要等人按下「检查更新」——
于是从不打开「关于」的人，永远不会知道有更新的版本存在。而这恰恰是这个程序本可以主动说出来、却没有说
的那件事。

这不是疏忽。`update_check.dart` 里写得很明白：检查器*「只在用户按下按钮时发问 —— 从不在启动时，也从
不按定时器」*，理由是「关于」页那句承诺 —— 这个程序做的一切都发生在本网络之内。所以这条需求不是「在哪
儿加个按钮」能满足的：要么悄悄把那句承诺破掉，要么公开把它改掉。而悄悄维持的承诺并不是承诺。

有三件事必须一起定，因为它们互相约束：这个问题允许问几次、答案放在哪儿、以及一条装着六个界面的侧栏怎
么给一个「不是界面」的东西腾位置。

## Decision

**静默地问一次，在启动时问，之后绝不自己再问。** `UpdateNotice` 只问一次，
`_LocalTransferAppState.initState` 不等待地把它发出去；按定时器问、或每次打开页面都问，仍然是禁止的。
「关于」页那个按钮照旧按需再问。一次运行最多两次请求，而那次没人让它发的请求不带任何本机信息。

**答案放在程序自己持有的 `ChangeNotifier` 里。** 它建在 `_LocalTransferAppState` —— 不是侧栏，因为
侧栏每次收到控制器变更都会重建，在那儿建一个 notice 就等于每重建一次就问一次 GitHub —— 然后作为构造
参数交给 `HomeShell`。这个参数可以为空，而这是刻意的而非将就：没有它的树（也就是每一个与更新无关的
widget 测试搭出来的那棵树）既没有入口，也什么都不问。

**一个检查器，两个发问者。** notice 通过 `UpdateResolution.checker` 发问，与「关于」页读的是同一个
缝，而不是自己再有一个。两条发问路径就是测试要顶替的两样东西，也是同一屏上两个可能互相矛盾的答案。

**用侧栏的 `trailing`，钉在底部。** `NavigationRail(trailingAtBottom: true, trailing: …)`。不做成
第七个 destination：destination 是「应用里的一个地方」，而这一个会离开应用去浏览器；而且列表中途多出第
七项，等于哪天多出第八个界面时，下面每一个标签都要挪位置。

**只有真有东西可拿时才画。** 问题还没回来时不画，答案是「已是最新」或「问不出去」时也不画。侧栏是一张
「东西都在哪儿」的地图，一个平时点了什么也不会发生的入口，就是地图上的噪声。

**版本号挂在 tooltip 上。** 标签只有一个词 —— `railUpdate`，「更新」 —— 而 `Tooltip` 载着
`l10n.aboutUpdateAvailable(version)`，也就是「关于」页为同一件事已经在用的那句话。同一个版本号有第二
种写法，就是多了一个让它俩走散的余地。

**按下它打开答案里那个 release**；响应里没给地址时退回 `updateReleasesPage`，与「关于」页用的是同一个
退路。打开网页地址这件事现在有了 `LinkOpener` / `LinkResolution`，与 `Revealer` 同形：它会交给操作系
统的 shell，所以驱动真身去跑的 widget 测试会在跑测试的机器上开出一个浏览器，而且永不返回。

**「关于」页那段文字被改了，而这次改动本身就是交付物。** 它原本写「以上一切都只在本网络内」。现在它写
的是：所有传送都只在本网络内，唯一的例外是启动时向 GitHub 问一次它发布了哪个版本，不发送任何内容。
哪天这句话又不成立了，那是代码的问题，不是文档的问题。

## Testing

`test_flutter/ui/update_rail_test.dart` 覆盖这个入口：本机已是最新时不在、问不出去时不在、位于六个界面
的第一个和最后一个**之下**而不是之中（tooltip 里带着新版本号，且悬停确实能把它显示出来）、按下时打开
答案里那个地址、答案没给地址时退回下载页，以及在没有侧栏的窗口里根本没有它。

让它可被断言的两道缝都在 harness 里：`ScriptedUpdateChecker`（否则这个问题会真的发一次请求出去）与
`ScriptedLinkOpener`（否则按下会真的开出浏览器）。`app_tree_test.dart` 现在装上前者，理由与它早就装上
一个记录型 host shell 是一样的；`about_page_test.dart` 也换成了它，替掉了自己那个私有替身 —— 整个测试
套件里从此只有一个脚本化检查器。

## Alternatives considered

**做成第七个 `NavigationRailDestination`。** 否决：它会被选中，于是 `selectedIndex` 需要一个「哪个界面
都不是」的取值；而且它会画在标签**之中**而不是之下 —— 这与需求正好相反，还会在下次加界面时把已有的每
个标签都挪走。

**把这次检查放到 `LocalTransferController` 上。** 否决，依据是这个项目用一条测试守着的分层规则：
`lib/app` 不许 import `lib/ui`，而 `UpdateChecker` 住在 `lib/ui`。唯一的路是把这个接口往下搬，代价则是
为了共用一条 `changes` 流，让控制器的主题 —— 设备、会话、传输 —— 里多出 GitHub 的 release。

**给 notice 做一个 `InheritedWidget` 作用域。** 否决：读它的只有一个 widget。`ControllerScope` 存在是
因为两棵树里的十几个 widget 都要读控制器；为唯一一个读者做一层作用域，等于多一层要理解的生命周期，而
且测试 harness 也得跟着装一层 —— 毕竟 harness 是直接搭侧栏的。

**留一个常驻入口，没新版本时写「已是最新版本」。** 否决：那会把一条只负责说明「东西在哪儿」的侧栏变成
一个常驻问号，而「这里没事可做」本身不是一个地方。

**用彩色圆点或角标代替文字。** 否决：侧栏里一个没有名字的圆点，是使用者最先学会忽略的东西；而且需求要
的就是一个写着「更新」的按钮。

**按定时器问，或每次打开页面就问。** 否决：那是把承诺悄悄地破掉，而不是公开地破掉。一次运行一次请求是
一句话能说清楚的；每次访问一次，不是。

**给一个关掉检查的开关。** 暂时否决：一个必须先被找到、否则这个程序就不按它自己「关于」页的说明行事
的开关，比一条写明白的例外条款更糟。真有人提出来，它就是显然的下一步，而改动只会落在 `UpdateNotice`
这一处。

**不动「关于」页那段文字。** 否决：它在这版发出去的那一刻就已经是假话了。

## Consequences

**换到了什么。** 有新版本这件事不用等使用者去问就会被说出来，每次运行只问一次，而「关于」页那个按钮依
然可以按需重新问一次。这个入口也不会被误认成一个界面，因为它本来就不是。

**那句承诺从此有了例外，而且被写下来了。** 在「关于」页的文案里、在 `update_check.dart` 里、在
`about_page.dart` 里，以及这里。今后任何想往外伸手的功能，都继承了「必须把自己写进那段文案」的义务
—— 这正是把它写在「关于」页而不是写在某份文档里的意义。

**没有侧栏的窗口里没有这个入口。** 窄窗口把侧栏换成底栏，而「左侧菜单栏最下方」没有一条左侧菜单栏可供
「最下方」。在窄窗口里，「关于」页仍然是检查更新的路。这一条被写进了测试，好让它一直是一个决定，而不
会某天变成一个意外。

**这个 notice 是没人等着的。** `UpdateNotice.check` 会兜住异常并回答 `UpdateCheck.unreachable` —— 那
本来就是这个接口已有的取值。这是替调用点兜的，不是替检查器兜的：将来某个违反契约的检查器，本该表现为
一个无人处理的异步错误，现在会表现为一个描述它的状态。

**widget 测试又多了一样要准备的东西。** 任何 pump `LocalTransferApp`（或持有 notice 的侧栏）的测试，
现在都要给一个答案 —— 因为这个问题是在启动时问的，不是在按下按钮时问的。`ScriptedUpdateChecker` 就是
那个答案，两个需要它的测试文件都在原地写清了理由。

**新增的 widget 测试一次都没有真正跑过。** 写这份笔记的机器上 `flutter test test_flutter` 起不来：
Dart 在那儿根本无法创建子进程（任何走管道的 stdio 都报 `ERROR_PIPE_BUSY`，来自一个第三方网络钩子），
于是 widget 套件、`dart test`、`flutter analyze` 和打包脚本全都不可用。上面那七个测试只做过静态检查
—— `dart format`，以及一次进程内的 `package:analyzer` 扫描（0 error / 0 warning）—— 仅此而已。回到能
用的工具链上，第一件事就是把它们跑起来。

**版本号和发布流水线不在这笔改动里。** `appVersion` 还是 `1.0.0`；把它降到 `0.1.0` 与打 tag 触发流水
线是接下来的两笔改动，而在第一个 release 真正发出去之前，这个入口不会亮起来。
