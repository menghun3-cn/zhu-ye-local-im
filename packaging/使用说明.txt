LocalTransfer 1.0.0 — Windows 绿色免安装版（x64）
=================================================
构建日期：2026-10-08
代码版本：develop @ 6f79a79

【怎么用】
1. 把整个文件夹解压到任意位置（桌面、U 盘都行）。
   注意不要只把 local_transfer.exe 单独拖出来 —— 它必须和 flutter_windows.dll、
   data\ 文件夹、三个 vcruntime/msvcp 的 dll 放在同一层。
2. 双击 local_transfer.exe 运行。界面默认就是中文。
3. 不需要安装、不写注册表、不需要管理员权限。想删除就直接删掉整个文件夹。

【界面上有哪几页】
- 设备：发现同网络里的其他设备、发起配对、查看已连接的设备。
- 对话：所有会话集中在这里，左边是会话列表、右边是聊天内容（见下一节）。
- 传输：发送与接收的历史记录（所有设备汇总在一起）。
- 剪贴板：剪贴板同步（关闭 / 问我 / 镜像 三档）。
- 设置：本机名称、身份指纹、接收文件的默认目录等。

【配对：点一下「接受」就完成了】
配对就是把两台设备放进同一个「设备组」。同一组里的设备随时可以互相发文件、
发消息、同步剪贴板；不在同一组的连不上。几个要点：

- 配对只做一次。程序会把对方记下来，以后每次启动都直接可用，不需要再做什么、
  也不会过期。
- 程序一启动就在监听别人的配对请求，不需要谁先去点「等待」。
  「设备」页上（本机卡片下面那张配对卡片里）有一个「应答配对请求」开关，默认开着，
  它下面写着「正在应答其他设备的配对请求」。关掉它，本机就不再接受新的配对请求
  （「设置」页的「配对请求」一栏会同步显示当前状态）。
- 谁都可以发起：在「设备」页找到对方，点它旁边的「配对」。不用输任何码、地址或端口。
- 被配对的一方会弹出一个「配对请求」窗口，上面写着是谁想跟你配对
  （那只是对方自己的说法，窗口里也用一句话写明了这一点），问你要不要放它进来。
  **点「接受」，配对当场完成 —— 没有第二步，不需要读数字，也不需要和另一台核对。**
  点「拒绝」，或者放着不管（大约 2 分钟后这次请求会过期作废），这次配对就结束，
  对方拿不到任何东西。
- 所以整件事只有两次点击：一边点「配对」，另一边点「接受」。
- 配对完成后，发文件、发消息、开连接都不再需要任何操作，可以同时对多台已配对设备收发。

【和一台设备说话：连上就直接进「对话」页】
连接和进入会话合并成了一步 —— 在「设备」页点对方卡片右侧的「连接」，
连接建立后程序会**直接切到「对话」页**，并且自动选中这台设备。
之后那张卡片会变成「打开会话」，再点一次就回到同一个对话。

「对话」页是微信那种双栏布局：
- 宽窗口：左边一列是会话列表，右边是聊天内容。
- 窄窗口：一次只显示一栏，点进某个会话后左上角有返回按钮退回列表。
- 会话名就是「设备名 · IP」，一眼看出在跟哪台机器说话。
- 会话列表里同时列出「当前连着」和「聊过但没连着」的设备，所以断线后记录还在。

聊天区里：
- 顶部一直显示对方的名字和它的 IP 地址；连接一旦断开，这里会标出「连接已断开」。
- 中间是历史：你发的在右边、对方发的在左边，文件显示文件名和传输进度。
- 底部是输入框（回车即发送）；左边回形针是「发送文件」，右边按钮是发送。
- 别人发来的文件会直接出现在这条会话里，就地显示「接受 / 拒绝」，不用再跑去别的页面。
- 右上角菜单里是「信任这台设备」。

【发文字不用对方确认，收文件仍然要】
这两件事的区别是有意的：

- **文字直接送达。** 你在对话里发了文字，对方那边立刻出现，不需要他点任何东西，
  也不会弹窗。文字只在内存里过一下，不落盘、不写文件，所以没有"收不收"这个问题。
- **文件要你确认。** 配对解决的是「谁可以连我」，不代表谁都能往你机器上写东西。
  别人给你发文件时，你这边会弹出传输请求，要你亲自点「接收」并选一个保存文件夹，
  文件才会落盘；不想收就点「拒绝」。这一步每次都要，不会因为配过对就免掉。

【数据写在哪】
- 设备身份与配对信息：%APPDATA%\LocalTransfer\profile.json
  也就是 C:\Users\<你的用户名>\AppData\Roaming\LocalTransfer\profile.json
  这是本机的设备身份（含密钥），删掉等于恢复出厂、需要重新配对。
- 收到的文件默认落在：%USERPROFILE%\Downloads\LocalTransfer\
  传输页里可以改成别的目录。

【怎么试（第一次配对不用输任何东西）】
注意：同一台机器上不要同时开两个本程序。发现用的是同一个 UDP 端口，
      只能被一个进程持有，第二个实例启动时会报端口占用。
      要真正试请用两台设备连同一个局域网：
1. 两边都打开程序，「设备」页应能互相看到对方。
2. 在其中一台，「设备」页找到另一台的名字，点它旁边的「配对」。
3. 另一台会弹出「配对请求」窗口，点「接受」。
4. 配对立即完成，发起方自动建立连接；在「设备」页点对方卡片上的「连接」，
   程序会直接跳到「对话」页，就能发文字和文件了。
5. 「剪贴板」页把同步档位打开，在任一台复制文本，另一台就会收到。
6. 如果两边在列表里都看不到对方：点「按地址连接」手动填对方 IP 直连
   （只对已配对设备有效，可当排查手段）。

【占用的网络端口（防火墙要放行）】
程序只用三个端口，全部在本局域网内，不连外网：
- UDP 47654：自动发现。两台设备要互相出现在列表里就靠它。
- TCP 47656：配对。对方点「配对」时拨的就是这个端口，本机必须允许入站连接。
- TCP 47655：配对之后的数据通道（发文件、发消息、同步剪贴板都用它）。

Windows 首次运行会弹出防火墙询问，请勾上「专用网络」再点「允许访问」。
如果当时点了「取消」，或者机器上装了别的安全软件，会出现：
- 「设备」页里看不到对方（UDP 47654 的入站被拦）；
- 点「配对」报「连不上对方设备：…… Connection timed out」（TCP 47656 的入站被拦）。

手动放行的办法（任选其一，改完不用重启程序）：
- Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 更改设置 →
  找到「局域网传输 / local_transfer」，「专用」和「公用」都打勾。
- 或者在「管理员」命令行里加一条入站规则：
  netsh advfirewall firewall add rule name="LocalTransfer" dir=in action=allow program="<解压目录>\local_transfer.exe" enable=yes profile=any
放行后，在另一台机器上可以用 Test-NetConnection <对方IP> -Port 47656 确认端口通了
（对方要保持程序在运行）。

【连不上时怎么排查】
- 报「连不上对方设备：…… Connection timed out」：多半是对方的防火墙拦了入站
  TCP 47656（见上一节）；其次是两台机器不在同一网段、或中间有隔离设备。
- 报「连不上对方设备：…… Connection refused」：对方程序没在运行，或者对方的
  「应答配对请求」开关被关掉了。
- 列表里看不到对方：检查两台机器是否在同一局域网、UDP 47654 是否被拦。
- 本机自己那张卡片写「监听：不接受连接」：说明本机还没加入任何设备组，
  先完成一次配对即可；如果是别人卡片上写这句，说明对方还没配对。

【已知限制（这版是给人试用的，请按这个预期看）】
- 发文件目前要手动填文件路径，没有文件浏览器。
- 会话历史只存在内存里：关掉程序就没了，重新打开是一条空会话。
- 没有「忘记设备」入口；要清掉就删 profile.json。
- 剪贴板镜像是轮询实现（约 0.7 秒一次），不是系统级监听，会有轻微延迟。
- 窗口标题和图标还是 Flutter 默认的（标题显示为 local_transfer）。
- 未做代码签名，首次运行 SmartScreen 可能提示“未知发布者”，
  点“更多信息”->“仍要运行”即可。
- 只在 Windows x64 上构建过；Android 版没有做过真机验证。

【系统要求】
- Windows 10 1809 或更高版本，64 位。
- 已随包附带 x64 的 VC++ 运行库（vcruntime140.dll / vcruntime140_1.dll /
  msvcp140.dll 就放在 exe 旁边），所以目标机器不需要另外安装任何东西。
- 首次运行请允许 Windows 防火墙放行（见「占用的网络端口」一节）。

【目录内容】
local_transfer.exe     主程序

【安全提示】
本程序只做局域网直连，没有服务端、没有账号、没有云端，不会主动往外网发数据。
所有流量都在本局域网内，端口见上文（UDP 47654 / TCP 47656 / TCP 47655）。

关于配对：这一版去掉了早期版本里「两边比对 6 位数字」的步骤。握手仍然会派生那组
数字、也仍然要用它给准入签名（两端必须一致才签得过），只是不再有界面把它显示出来、
也不再要求人去核对。也就是说：在同一个局域网里，凡是能完成握手、并且有一个人点了
「接受」的设备，就进了这个设备组 —— 这一步点击本身就是唯一的准入判断，请像对待
「允许某台机器连过来」一样对待它。
