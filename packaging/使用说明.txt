竹叶局域网传输 1.0.0 — Windows 绿色免安装版（x64）
=================================================
构建日期：2026-10-09
代码版本：wechat-ui-parity @ 7337c80

【怎么用】
1. 把整个文件夹解压到任意位置（桌面、U 盘都行）。
   注意不要只把 local_transfer.exe 单独拖出来 —— 它必须和 flutter_windows.dll、
   data\ 文件夹、三个 vcruntime/msvcp 的 dll 放在同一层。
2. 双击 local_transfer.exe 运行。界面默认就是中文。
3. 不需要安装、不写注册表、不需要管理员权限。想删除就直接删掉整个文件夹。

【界面上有哪几页】
- 设备：发现同网络里的其他设备、查看自动连接状态。
- 对话：所有会话集中在这里，左边是会话列表、右边是聊天内容（见下一节）。
- 传输：发送与接收的历史记录（所有设备汇总在一起）。
- 剪贴板：剪贴板同步（关闭 / 问我 / 镜像 三档）。
- 设置：本机名称、身份指纹、接收文件的默认目录等。
- 关于：当前版本号，以及「检查更新」（见下面「关于与升级」一节）。

【自动连接：发现后直接可用】
同一局域网里的设备一旦互相发现，程序就会自动建立设备组信任和数据连接。
没有「配对」按钮，没有配对码，也不会弹出「接受 / 拒绝」请求。

- 两台设备都打开程序，等到对方出现在列表里即可；通常几秒内完成。
- 不需要在另一台设备上确认，也不需要在「设置」里打开某个开关。
- 连接成功后可以直接发送文字、图片、文件和表情。
- 程序会记住设备组关系；重启、短暂断网或重新出现在同一网络后会自动恢复连接。
- 剪贴板共享仍是独立的显式选择：即使设备已自动连接，也要在「剪贴板」页勾选对方，
  本机复制的内容才会共享。

【和一台设备说话】
「对话」页会列出已经发现的设备。自动连接完成后直接点开对方即可发送内容；
如果某一端暂时还没连上，行尾会显示「正在自动连接」或「会自动重新连接」，
也可以点「连接」手动催一次。

「对话」页是微信那种双栏布局：
- 宽窗口：左边一列是会话列表，右边是聊天内容。
- 窄窗口：一次只显示一栏，点进某个会话后左上角有返回按钮退回列表。
- 会话名就是对方的名字；没报名字的设备显示它的 IP 地址，头像里是地址的最后一段
  （192.168.1.115 就显示 115）。
- 会话列表里同时列出「当前连着」和「聊过但没连着」的设备，所以断线后记录还在。

聊天区里：
- 顶部一直显示对方的名字和它的 IP 地址；连接一旦断开，这里会标出「连接已断开」。
- 中间是历史：消息是气泡，带头像。你发的绿底在右边，对方的白底在左边。
  只有图片不裹气泡：它就是一张缩略图，圆角、没有底色，和微信里一样。
  文件显示文件名和传输进度。
- 底部是输入框（回车即发送、Shift+回车换行）；左边回形针是「发送文件」，
  最右边按钮是发送。图片也走这一个回形针 —— 见下面「发文件 / 发图片」一节。
- 别人发来的文件会直接出现在这条会话里，就地显示「接受 / 拒绝」，不用再跑去别的页面。
- 文件落定之后，在聊天气泡上（或者在「传输」页的卡片上）**右键**，选「打开所在目录」，
  资源管理器会直接跳到它所在的文件夹 —— 不用自己去把这个目录找出来。
- 图片上**右键**有两条：「打开所在目录」和「复制图片」。选后者会把这张图放回系统剪贴板，
  接着就能粘进别的聊天窗口、文档或画图里。
- 别人发来的图片不用你确认：对方一发，图片就直接画在这条会话里，同时存进你设好的
  接收目录（见「设置」页）。
- 右上角菜单里是「信任这台设备」。

【发文件 / 发图片：同一个入口】
- 点输入框左边的回形针「发送文件」，弹出系统自带的文件选择框，文件和图片都能选
  （按住 Ctrl 或 Shift 可以一次挑多个）。
- 或者直接把文件或图片从资源管理器**拖到窗口里**，松手即发送。
- 两条路都不用手工指定类型：程序按扩展名分辨 —— 是图片（png / jpg / jpeg /
  gif / webp / bmp）就当图片发，其它当文件发。

图片发出去时不裹气泡，就是一张缩略图。点一下放大看（再点一下或点外面关闭），
右键可以「打开所在目录」或「复制图片」。对方那边收到的图片也一样。
进度：图片还在传的时候，缩略图下面有一条进度条；传完就没有了。

【发文字和图片都不用对方确认，收文件仍然要】
这几件事的区别是有意的：

- **文字直接送达。** 你在对话里发了文字，对方那边立刻出现，不需要他点任何东西，
  也不会弹窗。文字只在内存里过一下，不落盘、不写文件，所以没有"收不收"这个问题。
- **文件要你确认。** 自动连接解决的是「哪些设备在同一设备组里」，不代表谁都能往你机器上写东西。
  别人给你发文件时，你这边会弹出传输请求，要你亲自点「接收」文件才会落盘；
  不想收就点「拒绝」。这一步每次都要，不会因为已经自动连接就免掉。
  点了「接收」就直接收下，文件进「设置」页里那个接收目录，**不会再弹窗问你
  存到哪** —— 点「接收」就是完整的回答。（只有这台机器连接收目录都没有时，
  才会让你现选一个文件夹。）
- **图片也不用确认，直接显示。** 图片和文字一样「到了就到」：对方一发，这边立刻画出来，
  同时存进「设置」页里那个接收目录，不会弹窗问你收不收。

【对方没报上名字时，显示的是它的 IP 地址】
正常情况下列表里显示的是对方自己起的名字。「自己起的」这点要知道 —— 名字是对方
自称的，本机无法核实。所以当对方根本没报名字时（刚装好还没改过名、或者对方那个
客户端就不带这个字段），这一栏显示的是**它在网络里的地址**，头像里是地址的最后一段：

- 对方是 192.168.1.115，列表里就写 192.168.1.115，头像里写 115。
- 地址回答的是「这是哪台机器」：两台都没名字的设备同时出现时，一眼就能分清，
  也能直接拿它去 ping、去路由器上找。
- 地址是本机**自己看到的**，不是对方给的，所以它和指纹一样比名字可信。
- 连地址都还没有的设备（在设备组里、但从来没被听见过的），才退回显示指纹开头几位。
- 你自己这台机器的名字不受影响：没改过名之前，它仍然叫「Unnamed device」。
  想改成好认的名字，在「设备」页点「重命名」。

【数据写在哪】
- 设备身份与自动连接关系：%APPDATA%\LocalTransfer\profile.json
  也就是 C:\Users\<你的用户名>\AppData\Roaming\LocalTransfer\profile.json
  这是本机的设备身份（含密钥），删掉等于恢复出厂；附近的设备会在重新发现后自动建立新关系。
- 收到的文件和图片默认落在：%USERPROFILE%\Downloads\LocalTransfer\
  （在「设置」页里可以改成别的目录；接收文件不再每次询问，一律进这个目录。）

【怎么试（第一次连接不用输任何东西）】
注意：同一台机器上不要同时开两个本程序。发现用的是同一个 UDP 端口，
      只能被一个进程持有，第二个实例启动时会报端口占用。
      要真正试请用两台设备连同一个局域网：
1. 两边都打开程序，「设备」页应能互相看到对方。
2. 等几秒，两边会自动建立连接；「对话」页会出现对方，直接点开就能发文字、文件和图片。
   点输入框左边的回形针，文件和图片都能挑（程序按扩展名自动分辨）；也可以
   直接把文件从资源管理器拖进窗口。
3. 「剪贴板」页把同步档位打开，并勾选对方，在任一台复制文本，另一台就会收到。
4. 如果两边在列表里都看不到对方：点「按地址连接」手动填对方 IP 直连
   （只对本机已经属于同一设备组的设备有效，可当排查手段）。

【占用的网络端口（防火墙要放行）】
程序只用三个端口，全部在本局域网内，不连外网：
- UDP 47654：自动发现。两台设备要互相出现在列表里就靠它。
- TCP 47656：自动建立设备组信任时使用，本机必须允许入站连接。
- TCP 47655：建立信任后的数据通道（发文件、发消息、同步剪贴板都用它）。

Windows 首次运行会弹出防火墙询问，请勾上「专用网络」再点「允许访问」。
如果当时点了「取消」，或者机器上装了别的安全软件，会出现：
- 「设备」页里看不到对方（UDP 47654 的入站被拦）；
- 自动连接一直失败并报「连不上对方设备：…… Connection timed out」
  （TCP 47656 的入站被拦）。

手动放行的办法（任选其一，改完不用重启程序）：
- Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 更改设置 →
  找到「竹叶局域网传输 / local_transfer」，「专用」和「公用」都打勾。
- 或者在「管理员」命令行里加一条入站规则：
  netsh advfirewall firewall add rule name="LocalTransfer" dir=in action=allow program="<解压目录>\local_transfer.exe" enable=yes profile=any
放行后，在另一台机器上可以用 Test-NetConnection <对方IP> -Port 47656 确认端口通了
（对方要保持程序在运行）。

【连不上时怎么排查】
- 报「连不上对方设备：…… Connection timed out」：多半是对方的防火墙拦了入站
  TCP 47656（见上一节）；其次是两台机器不在同一网段、或中间有隔离设备。
- 报「连不上对方设备：…… Connection refused」：对方程序没在运行，或对方还在启动。
- 列表里看不到对方：检查两台机器是否在同一局域网、UDP 47654 是否被拦。
- 本机自己那张卡片写「监听：正在自动建立连接」：等待自动握手完成即可。
- 如果写「监听：连接通道暂未就绪」，通常是 TCP 47655 端口绑定失败；
  先检查是否有另一个本程序实例占用了端口。

【已知限制（这版是给人试用的，请按这个预期看）】
- 会话历史只存在内存里：关掉程序就没了，重新打开是一条空会话。
- 图片是整张读进内存再画的。特别大的图（几十 MB）会占较多内存，也可能显示得慢。
- 没有「忘记设备」入口；要清掉就删 profile.json。
- 剪贴板镜像是轮询实现（约 0.7 秒一次），不是系统级监听，会有轻微延迟。
- 图标还是 Flutter 默认的；窗口标题已经是「竹叶局域网传输」，「关于」页里写着当前版本号。
- 未做代码签名，首次运行 SmartScreen 可能提示“未知发布者”，
  点“更多信息”->“仍要运行”即可。
- 只在 Windows x64 上构建过；Android 版没有做过真机验证。

【关于与升级】
- 「关于」页写着当前版本号和升级办法，并有一个「检查更新」按钮。
- 点「检查更新」会去 GitHub 查这个项目有没有发布过更新的版本。这是本程序**唯一**
  一次主动访问外网的动作，而且只有你点它才会发生：不点，程序就只和局域网说话。
  查到新版本会把版本号显示出来，也可以点「打开下载页」用浏览器打开。
- 升级就是换一套文件：退出程序 → 下载新版压缩包 → 解压后覆盖原来的目录即可。
  %APPDATA%\LocalTransfer\profile.json 是本机身份（含密钥），**不要删**；覆盖安装
  也不会动它。
- 同一个版本还会同时发布一个安装包（LocalTransfer-x.y.z-windows-x64-setup.exe）：
  装到用户目录、有开始菜单项与卸载项、不需要管理员权限。两种装法用的是同一份程序
  文件，选一种即可 —— 不要两份都装还同时开着。安装包自带的说明是「安装说明.txt」。

【系统要求】
- Windows 10 1809 或更高版本，64 位。
- 已随包附带 x64 的 VC++ 运行库（vcruntime140.dll / vcruntime140_1.dll /
  msvcp140.dll 就放在 exe 旁边），所以目标机器不需要另外安装任何东西。
- 首次运行请允许 Windows 防火墙放行（见「占用的网络端口」一节）。

【安全提示】
本程序只做局域网直连，没有服务端、没有账号、没有云端，不会主动往外网发数据。
所有流量都在本局域网内，端口见上文（UDP 47654 / TCP 47656 / TCP 47655）。

关于自动连接：同一局域网里的设备通过自动发现建立设备组信任，随后自动打开数据连接。
握手仍会派生短认证串并用于绑定准入签名，但不再显示数字，也不再要求任何人比对或确认。
请只在可信的局域网里运行本程序；剪贴板共享和文件接收仍有各自独立的授权步骤。
